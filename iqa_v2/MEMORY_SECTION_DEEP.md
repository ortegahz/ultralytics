#### 一、A1 FAIL —— 曲线**没有塌**，膝点只能叫「弯折点」

`common_good` 池（874 窗口）× 三臂，deep 各族**最重档**的实测跟住率
（见 `iqa_v2/REPORT_V2_DEEP.md` §4.1 / `iqa_v2/output_deep/degrade_detail_v2.csv`）：

| 退化族 | 最重档 | n | XCorr | KCF legacy | CSRT |

🔴 **结论**：**没有任何一个「族 × 臂」组合跌破 50%**；全表 15 格中 **13 格**仍在 90% 以上。
⇒ 膝点定位在「**画质—跟踪性能分界点 / 弯折点**」，**不是**「**跟踪崩溃点**」，
**不足以产生跟踪崩溃** ⇒ 对外措辞**必须继续保留**这个限定，**不许**升级成「崩溃点 / 红线」。
（规格书 A1 的失败条款因此触发：如实写「本方法在净化底座上无法造出崩溃点」。）

🔴 **根因（重要，且是本轮最反直觉的一条）**：三族退化都作用在**整帧**上，
跟踪器在**大目标**上仍有很强的形状先验 ⇒ 把上限从 σ=4 抬到 σ=8 **对跟住率几乎无效**。
⇒ **「塌不下去的是跟住率，不是指标轴」**；要想让跟住率真塌到 50% 以下，
需要的是**目标级**退化（逐目标贴图涂抹 / 遮挡 / 淹没），不是整帧的模糊与拖影。

### 八、🔴 铁律（本轮新增，沉淀进 `manu/memory/rules.md`）

#### 1. 🔴🔴【2026-11-27 新增】**判据必须写死在「任何结果落盘之前」的独立文件里，并配一个只吃 CSV、不采信报告正文的机器判定器** —— 否则报告会被「修」成自洽，判据就废了

深轮的做法是：**先**落 `iqa_v2/DEEP_AXIS_SPEC_20261127.md`（写明 A1~A4 / B1~B5 / C1~C4 与阈值），
**后**跑流水线；判定器 `iqa_v2/acceptance_deep.py`（纯标准库、**22 条判定**）
**只读产物 CSV 现场重算**，**不复述**报告正文里的任何数字 ⇒ 报告与产物不一致时，
以判定器为准。🔴 **还要配「反向判据」**（本轮 B1~B6）：专门防「为了让结论好看而偷偷放松口径」——
门槛不许动、盲测集零参与阈值搜索、池子不变、线位取最严、不得比基线更松、档位表与规格逐位一致。
📌 **可执行**：任何一轮「加码 / 换轴 / 换底座」的实验，**先交规格文件 + 判定器**，再开跑；
规格文件与判定器**两个都**交不出来 ⇒ 这一轮不许开始跑。

#### 2. 🔴🔴【2026-11-27 新增】**曲线塌不下来就只能叫「弯折点」——对外措辞不许升级，且加深档位必须由实测判据裁定** —— 「加深轴」不是「让结论更硬」的通用手段

本轮把 `blur` σ 上限 **4.0 → 8.0**、`motion` 核长上限 **11 → 15**、`contrast` α 下限 **0.15 → 0.05**，
最重档跟住率最低仍 **87.9%**（blur/xcorr）⇒ **A1 FAIL** ⇒ 膝点只是「**画质—跟踪性能分界点 / 弯折点**」，
**不是**「**跟踪崩溃点**」，**不足以产生跟踪崩溃** ⇒ 对外措辞**必须继续带这个限定**。
🔴 且根因要说清楚：整帧级模糊与拖影**打不塌**跟住率（跟踪器在大目标上有强形状先验），
要塌得下去得用**目标级**退化 ⇒ **「加档位」不是通用药**，它解决的是**指标轴区分度**，不是**跟住率塌陷**。
📌 **可执行**：写红线 / 写对外材料前，先问「这条线对应的是弯折还是崩溃」；
判据里**必须**同时写死**通过线**（本轮 50%）与**失败时的处置条款**，不许事后解释。

#### 3. 🔴🔴【2026-11-27 新增】**报告正文必须由 CSV 现场生成、禁止手抄：结论表必须与 CSV 逐格对账，且缺陷要修在生成器里、不是 Markdown 里** —— 表格换新数据而正文留旧措辞 = 同一份报告自相矛盾

深轮踩过的坑：深轮报告由**基线轮的生成器**产出 ⇒ **表格**是 deep 的、**正文段落**是基线轮的
（6/5/6 档位阶梯、「跟住率仍在 90% 以上」、基线参照读数 505.62 / 541.09 / 1110.81、
「只有 XCorr 一条臂过守卫」）；更隐蔽的一类是**脚本里硬编码的档位阶梯**
（复算器写死基线 6/5/6 ⇒ 深轮下**静默丢掉**新增档位，只覆盖浅半段轴）。
🔴 **修 Markdown 没用**——下次重跑报告就被覆盖 ⇒ **必须改生成器**。
🔴 **修法**：① 档位阶梯一律**从明细底表实测反推**，明细缺失时**显式 FAIL/WARN**，
**不许**静默回落成基线阶梯后「空过」；② 判定器设**逐格对账**项（本轮 D1~D8：
逐档跟住率 50 个读数、曲线分级 9 条跨度、约束线 3 条线位、盲测 3 组数字、判据总表单元格、
最重档读数、交叉引用可达性、对外阈值精度）⇒ **正文与 CSV 不一致 ⇒ 判定 FAIL**。
🔴 **本轮收尾又踩了同一类坑的「变种」**：① 报告 §11.1 把基线清单的失败项**硬写**成「6 条漂移代码 + 1 条 cache 明细 /
第 7 条失败」，实测是 **7 条**（漏了术语统一后一并改动的 `regression_v2.py`）⇒ **交付正文里出现假陈述**
⇒ 修法：这类数字一律**现场拿两份清单对账**（基线清单 vs **深轮清单**登记的代码 md5）自动算，两台机器读同一份深轮清单 ⇒ 数字**两侧逐字相同**；
② `compare_rounds.py --strict` 判 `verdict: NEEDS_ACTION` / `notes_required: 3`（决定臂 `xcorr` → `kcf_legacy`、
决定族 `motion` → `blur`）⇒ 工具**要求报告披露**，而报告原先**没披露** ⇒ **工具判了 NEEDS_ACTION 也等于没交**
⇒ 现已在报告 §6.2 **逐条披露**。
📌 **可执行**：凡是有「数字结论」的报告，一律**只允许由 CSV 生成**；手工编辑过的报告 = 未通过验收的报告。

#### 4. 🔴【2026-11-27 新增】**大体量明细不能用裸 md5 进清单，必须走顺序无关规范摘要** —— 否则「重跑必假失败」，把行序抖动误判成数据变化

`run_eval_v2.py` 用多进程池以 `imap_unordered` 收集 `(窗口 × 条件)` 明细行 ⇒ **同一份输入重跑一次行序就变**
⇒ 对 `degrade_detail_v2.csv`（本轮 **24 817 行 / 47 列**）做裸 md5 **必然假失败**，
而且这种失败**证明不了任何东西**。
📌 **可执行**：大体量明细改用 `iqa_v2/canonical_digest.py` 的**顺序无关规范摘要**
（规范化口径固定：关键列唯一 + 按表头顺序取值的规范行串 + **排序后**再摘要 ⇒ 只改列名摘要也会变），
由清单旁挂 `*.bulk.canonical.txt` 登记并 `verify`；本轮实测：重跑整轮深轮后该摘要
**24 817 行 / 47 列 / 0 处差异**，其它 CSV **8/10 逐字节相同**（`segment_class_v2.csv` 仅行序不同、
`correlations_v2.csv` 仅 pearson 末位 ULP 噪声）⇒ 这才是**有效**的复现性证明。

#### 5. 🔴【2026-11-27 新增】**清单里的代码条目要跟「冻结代码镜像」核对，不能跟活代码核对；且默认 `--out` 不许原地覆盖已交付的冻结清单** —— 否则「本轮改代码」会被误判成「基线产物被篡改」

深轮改了 `run_eval_v2.py` 等 **7 个**代码文件（`audit_final.py` / `degradation_4d.py` /
`make_manifest_v2.py` / `recheck_curves.py` / **`regression_v2.py`**（术语统一一并改到）/
`run_eval_v2.py` / `test_iqa_v2.py`）⇒ 冻结清单 `iqa_v2/output/manifest_v2.md5` 的**代码条目** md5 必然对不上
（**当前 host 实测 rc=1，OK 17 / FAILED 8**：**7 条是代码条目**（深轮继续演进的活代码）＋ **1 条是 cache 侧绝对路径**
`/tmp/iqa_v2_cache/degrade_detail.csv`（host 上无此中间产物，服务器侧有且一致）⇒ 该条在 host 报「不可读」、
在服务器侧计入 OK ⇒ 服务器侧同口径 **rc=1（OK 18 / FAILED 7）**；
**产物条目 14/14（host）／15/15（服务器，含 cache 明细）全 OK**）。
📌 **这 7 条不是手抄的**：报告 §11.1 现在**现场拿两份清单对账**（基线清单 vs **深轮清单**登记的代码 md5）自动算
⇒ 两台机器读同一份深轮清单 ⇒ 数字**两侧逐字相同**。
🔴 **这是预期现象，不是基线产物被改动**：基线清单自身 md5 生成前后均为 `a72bc7fa5c267b853943416fb2670820`。
📌 **可执行**：① 代码条目的核对基准是**冻结镜像** `iqa_v2/_baseline_code_20261126/`（pytest 走这条），

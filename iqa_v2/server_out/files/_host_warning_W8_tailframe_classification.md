## 一、结论先行

27 行 `clean_success_rate = 0.99784` 全部由**同一个窗口**造成。改分类口径一处，这 27 行同时变绿。

| 项 | 实测 |
|:--|:--|
| 不达标膝点行 | **27** 行，全部是 `kcf_legacy / own_good / small` × 3 族 × 9 指标 |
| `clean_success_rate` | 全部 = **0.99784** |
| 数学吻合 | `1 − 1/463 = 0.997840` ✅ **精确吻合**（463 = kcf 好片段∩小目标∩calib 的窗口数） |
| 对照：`all` 层 | `1 − 1/1259 = 0.999206` ⇒ **不破 0.999**（所以只有 `small` 层挂） |
| 唯一肇事窗口 | **`3700000000002_105103_6` / frame `1495`** |

## 二、根因（逐字段可核）

该窗口在 `segment_class_v2.csv` 里：

```
seq_id=3700000000002_105103_6  frame_id=1495
w=6.0  h=5.0  tolerance=5.0
cle_kcf_legacy=2.5495  maxcle_kcf_legacy=2.5495  complete_kcf_legacy=1
class_kcf_legacy = good          ← 分类器说「好片段」
```

而在 `degrade_detail.csv` 的 **clean 行**里：

```
kcf_legacy_ok=1  complete=1  success=0   err='no_tail_frame(滞后一帧读数)'
xcorr_success=0（complete=0）    csrt_success=0（maxcle 5.385 > tol 5.0）
```

⇒ **这个窗口三臂全失败**，唯独 KCF 臂被分类器判成了「好片段」。
机制：**分类器只看「末帧 CLE ≤ 3px + 全程跟住」，没看「尾帧读数是否存在」**。

- 任务书 §一.1 的好片段定义就是「末帧 `CLE_{t+4} ≤ 3px`」⇒ 分类器**照任务书做是对的**；
- 但交棒书 §2.1 同时要求：**KCF `update()` 滞后一帧 ⇒ 序列末尾拿不到尾帧的窗口（205 条 / 8.4%）必须显式标注**；
- 这条窗口正好卡在两个口径的缝里：`cle_end` 实际取自 t+4（不是补偿后的 t+5），
  **跟住率标志因此判 0，而分类器仍按「末帧 CLE ≤ 3px」判 good** ⇒ **两个数不同源**。

## 三、影响面（比红灯本身大）

host 侧在 2442 个 clean 行上统计 `err` 含 `no_tail_frame` 的行：

| 项 | 实测 |
|:--|:--|
| 带 `no_tail_frame` 的 clean 行 | **205**（正好对上交棒书点名的 205 条 / 8.4%） |
| 其中被判 `class_kcf_legacy=good` | **154** |
| 其中进了退化仿真池 | **117** |

⇒ 目前**只有 1 个**翻转了跟住率（就是上面那个窗口）；
但这 **117 个窗口的 `cle_end` 不是真实测量值**（KCF 尾帧缺失，读的是 t+4 未补偿值），
⇒ 交棒书要求的「**必须显式标注**」这一条**尚未落地**。

---

## 四、建议修法（两条，任选其一；**不要放宽断言阈值**）

1. **让分类与跟住率同源**：`class_*` 判 good 时，同时要求 `*_success == 1`
   （等价于 `complete ∧ maxcle ≤ tol ∧ 尾帧存在`）；或把 `err` 含 `no_tail_frame` 的窗口
   单独标成一类（如 `class_* = no_tail`），**不参与好片段池**。
2. **或在 `extract_knee` 侧显式剔除**：计算 `clean_success_rate` 时，
   对含 `no_tail_frame` 的窗口单独计数并写进产物（如新增列 `n_no_tail_frame`），
   让「起点跟住率」只反映**真正有尾帧读数**的窗口。

🔴 **不建议**把断言从 `>= 0.999` 放宽到 `< 0.99`：那会把「读数不存在」当成「读数不好」，
**污染底座纯净度的语义**。本轮要求的是「起点 ≈ 100%」，
正确的做法是**让不该进池的窗口不进池**。

📏 **成本**：改分类口径后**只需重跑 knee 阶段 + 约束线 + 回归 + 报告**（明细不用重跑），
但分类改动会影响 `segment_class_v2.csv` ⇒ **Pass A 需要重跑**（约 0.4 分钟，很便宜）。

### 三、为什么 contrast 族会这样（数学原因）

任务书 §四.2 明确要求「退化强度递增 ⇒ 局部画质指标单调下降」这条**单调性假设**。
对 `contrast` 族（`I' = αI + (1-α)μ`）：

- `local_scr = P90(|I_core − μ_ring|) / (σ_ring + 1e-5)` ⇒ 分子分母**同时乘 α** ⇒ **数学上不变**；
- `target_local_contrast` 分母含 `μ_ring`，同样近似不变；
- 而 XCorr / KCF 都是**归一化**匹配 ⇒ 对整体对比度缩放近乎免疫 ⇒ **跟住率不随 α 塌**。

| blur | 63.8% | 45.0% | 94.2% |
| motion | 32.9% | 18.5% | 68.5% |
| **contrast** | **8.2%** | 76.0% | 96.5% |

⇒ **contrast 族对 `local_scr` 基本不承载信息**，这一族的 `local_scr` 膝点**无物理意义**。

### 三、🔴 本轮的核心真缺陷修正（曲线守卫口径）—— 这是本轮**最重要**的一处工程修正

* **症状**：上一版发出的 `target_lap_var < 541.09` 被当成可用红线，但它的**双算法「0.00% 一致」是伪一致**。
* **根因（用真实数据独立复算确认，非猜测）**：守卫把**逐档跨度**（受控退化轴口径）写进 `curve_y_span` 列，
  **但膝点实际取自「分箱曲线」**（X = 实测指标值、Y = 该值下的跟住率）⇒ 等于「**用 A 曲线的健康度给 B 曲线放行**」。
  实测 `target_lap_var` / XCorr / `motion`：**逐档跨度 6.41 pp**（过门槛）但**分箱跨度仅 1.92 pp**
  ⇒ 整条曲线几乎是平的（跟住率在 0.940~0.976 之间抖动）⇒ 所谓膝点 **541.09** 只是「曲线上一个噪声局部极大值处的**分箱边界**」。
* **修法**：守卫改判在**膝点自己的曲线**（分箱曲线 `curve_y_span`）上，逐档跨度降为**第二道**守卫并单列 `level_y_span`；
  `phase_constraint` 同步双跨度守卫；`verify_recalc_v2.py` 用**独立实现**复算两条跨度并双向对账。
* **后果（必须写进对外结论）**：`target_lap_var` **本轮没有有效红线**（`constraint_lines_v2.csv` 里显式记 `nan` + 写明原因，
  `audit_final.py` R5k 守住）⇒ 按任务书 §二.3「否则降级为物理参照」⇒ **不进约束线表、不进免责声明**；
  上一版发出的 **541.09 作废**；**对外可发布版只保留 `target_local_contrast < 0.1891664` 一条**。

## 1. 三臂定义（用户最终拍板，**不再改动**）

| 臂 | 机制 | 代码位置 |
|:--|:--|:--|
| **臂 1 纯检测基准** | 不跟踪。第 t 帧直接甩第 t−Δ 帧算出来的旧检测框（det_hz=25、Δ=8 ⇒ 每帧都有输出，静态硬吃 320 ms） | `arms.py::arm1_detector_only` |
| **（对照）臂 1 同锚点密度（det_hz=12.5）** | 与臂 1 同一机制，**只把检测频率降到与臂 2/臂 3 相同**（det_hz=12.5）⇒ 消除"锚点密度"这个混淆变量 | `arms.py::arm1_detector_only_sparse` |
| **臂 2 检跟纯前向外推** | 快核每帧前推；迟到检测**只对比、不回溯、不修正**；`detection_reinit=False` ⇒ 检测流**永远不能**把位置搬回旧检测点 | `arms.py::arm2_forward_only` |
| **臂 3 异步退回重推演** | 迟到检测作第 t−Δ 帧的**绝对锚点**，从帧环形缓存逐帧重推 Δ−1 步到第 t−1 帧，由主流程走完第 t 帧，覆盖当前状态并回写历史；**不加任何人为平滑衰减** | `arms.py::arm3_rollback_replay`、`replay.py` |

**机制开关**：`TrackerConfig.fusion_mode ∈ {"alpha", "replay", "none"}`（`tracker.py`）；
**速度源开关**：`TrackerConfig.velocity_source ∈ {"none", "history", "detection"}`（`tracker.py` / `fusion.py`，**默认 `"none"`**，见 §6）。

> ⚠️ **为什么要加"（对照）臂 1 同锚点密度"这条臂**：臂 1 原本 det_hz=25（每帧一个锚点），
> 而臂 2/臂 3 是 det_hz=12.5（每 2 帧一个锚点）⇒ **锚点密度**是横跨两组的混淆变量，
> 直接比臂 1 与臂 2/臂 3 的命中率是不公平的。这条对照臂把臂 1 的锚点密度也降到 12.5 Hz，
> 于是"同锚点密度"下才可比。
> **它的 headline 22.39% 是覆盖率 artifact**：det_hz=12.5 ⇒ 只有 45.5% 的帧上有输出
> （`frames_with_output` 4973 / 10535），
> 全序列分母里另外 54.5% 的帧它**根本没输出**（按口径算未命中）。
> **公平比较看存活窗口命中率**：对照臂 49.22%
> vs 臂 1 49.06% vs 臂 3 55.41%
> —— **同一锚点密度下，检跟分离两条臂"活着时跟得准不准"明显更好**，这才是同密度对照的结论。

## 5. 三个天花板（**决定结论的关键**）

> 这三个数与本 harness 的实现无关，只取决于**快核能力**与**目标/检测器本身**。
> 没有它们，就分不清"臂 3 效果不好"是**实现不行**还是**前提不成立**。

| 天花板 | 数值 | 含义 |
|:--|:--|:--|
| **快核单步局部误差**（从真值锚点走 1 步） | p50 = 2.22 / p90 = 9.22 / p95 = 13.89 / p99 = 29.97 px；单步有效率 0.866 | 快核一步就有 2.22 px 误差（龙泉山目标是**成簇亮点**：本体+拖尾 ⇒ 质心被拖尾拽偏）。**纯内核能力看 `single_step_error_px_valid_only`**：p50=2.32 / p90=9.04 / p95=13.46 / p99=29.52 px（n=9,112，只含 valid 样本） |
| **重推 Δ 步的累积误差**（从**完美**锚点出发） | p50 = 3.66 / p90 = 13.77 / p95 = 18.76 / p99 = 45.37 px | 这就是臂 3 的**理论天花板**；实跑还要叠加锚点（检测器）误差。能走完 Δ 步的样本 8,459 帧 |
| **锚点误差**（检测框在它自己那一帧） | p50 = 1.87 / p95 = 29.75 / p99 = 341.28 px | 重推演消**不掉**它——消的是累积漂移，不是锚点偏差 |
| **目标在 Δ=8 帧内的真实位移** | p50 = 3.54 / p90 = 51.05 / p95 = 91.47 / p99 = 179.71 px | 纯检测臂的误差 ≈ 锚点误差 ⊕ 这一项 |
| **单帧位移 > ROI 半窗(16 px) 的帧占比** | 3.83% | 快核 32×32 视野追不上的帧 |

> ⚠️ **三个数的样本集合不同，不可直接相减**：
> `single_step_error_px`（n=10,527）**含 invalid 样本**——
> invalid 时快核位置不动，此时"误差"其实是目标真实位移而非内核误差 ⇒
> **想看纯内核能力请用 `single_step_error_px_valid_only`**（n=9,112）；
> `delta_step_error_px`（n=8,459）**只含走通 Δ 步的样本**。
> 另：锚点误差的样本集 n=9,650、锚点口径的 Δ 帧位移 n=10,447
> （p50=3.54 / p95=84.69 / p99=171.51 px），
> 与上表"可跟性前提"那套（n=10,527）**也不是同一个集合**。

**结论**（注意这是**理论下界 vs 实测**的对比）：臂 1 的误差 ≈ 锚点误差 + Δ 帧位移，
**实测 p50 = 5.19 px**；臂 3 的误差 ≈ 锚点误差 + 重推累积误差，
**理论下界 p50 = 3.66 px**（完美锚点）、
**实测 p50 = 4.35 px**。⇒ 臂 3 的 p50 比臂 1 好 16%，
但臂 3 的实测值比它自己的理论下界（3.66 px）还高 19%
⇒ 本序列上"退回重推演"**换不来量级优势**，只能换来**百分点级**优势。

## 6. 速度源对照（三档可切换，默认 `"none"`）——**本轮语义修正 + bug 修复**

### 6.1 规格自身不一致（**这是本轮 bug 的源头**）

设计文档对"硬拉回到当前时刻该落到哪"给了**两套互相矛盾**的说法：

- **§二.3 散文**（情况 B）：位置 = 检测位置 **+ 历史运动速度 v × Δ**；
- **§三 Python 伪代码骨架**：`self.curr_pos = np.array(det_xy)`（**直接落在检测框，不投影**）。

实现照 §二.3 写 ⇒ 真实序列上是**负收益**。⇒ 代码改成**三档可切换**，并把默认值定在
**实测更优、且与 §三 伪代码一致**的那一档：

| 速度源 | 语义 | 对应文档 |
|:--|:--|:--|
| **`"none"`**（**默认**） | **不投影**，直接落在检测框 `z_f` | §三 伪代码 `curr_pos = np.array(det_xy)` |
| `"history"` | 用**快跟踪器自己的历史速度** v × Δ 投影 | §二.3 散文 |
| `"detection"` | 用**检测流速度**（最近若干次关联上的检测）投影 | §二.3 散文的一个变体 |

代码位置：`fusion.py::FusionConfig.velocity_source`、`fusion.py::ResidualFusion._resolve_velocity`、
`tracker.py::TrackerConfig.velocity_source`、`tracker.py::_project_to_now`。

### 6.2 真 bug：**0 是合法速度，不得因速度为 0 换源**

旧实现（"历史速度为 0 ⇒ 用检测流速度兜底"）在 Gate 3b 的双斑合成场景里翻车：
目标**静止**⇒ 历史速度合法地等于 0 ⇒ 代码却换成**检测流速度**，
而检测流此时已**切换到另一个目标**⇒ 拿到脏速度 **−2.857 px/帧**，乘 Δ=2 ⇒
**5.71 px 假位移** ⇒ **Gate 3b 一直 FAIL**。

- **修法**：**0 是合法速度**，不再因速度为 0 换源；检测流速度只在**历史速度取不到**
  （环形缓冲里没有可用帧）时兜底。
- **更深一层的根因**：硬拉回能触发的前提就是"**快跟踪器已经锁在杂波上**"，
  此刻它的历史速度**正是杂波的速度** ⇒ 拿它投影只会把刚拉回的目标**再甩出去**。
- **结果**：**Gate 3b 由 FAIL 转 PASS（实测 0.0 px）**。

- **臂 3 为什么"不适用"**：臂 3 的校正是 `replay` **整段重定位**（从锚点逐帧重推 Δ−1 步），
  属**设计内的大跳变**（校正帧 StepJump p95 = 8.03 px，
  max = 115.46 px，3,422 个校正帧中
  645 帧 > 2 px）⇒ **smooth 桶为空**，
  该判据对它**没有定义**，不能拿"没有超过 2 px 的平滑帧"当成通过。
- **定量换算（为什么 α=0.4 / gating=12 px 结构上就不可能过）**：
  残差平滑融合的一次校正位移上界是 **α·e ≤ 0.4×12 = 4.8 px**
  （α = 0.4，gating 半径 = 12 px）⇒ **单是上界就已经 > 2 px**；
  要满足 ≤ 2 px，残差本身必须 ≤ 5.0 px。
  实测 alpha 的 smooth 桶 p95 = 5.74 px ⇒ **判据不成立**。
- ⇒ **结论：规格判据 1 在 α=0.4 / gating=12 px 下不成立**（本轮语义修正后**依然**不成立）。
  **不得写成"通过"**；要么改判据的适用对象，要么改 α / gating 参数（见 §15）。

## 13. 踩坑清单（本周四/五 + 本轮）

1. **快核底噪估计必须解耦**（文档原版被实测打脸）：龙泉山目标是**成簇亮点**（本体+拖尾），32×32 ROI 内目标占比 60~80% ⇒ ROI 内中值/MAD 被目标自己抬高 ⇒ 门限高过峰值 ⇒ 每 ~14 帧误判"无信号"。改为**小窗(32)提质心 + 大窗(64)估底噪**：真值处有效率 0.704→0.873。
2. **`peak_centroid` 在簇状目标上明显更差**（p50 5.13 vs centroid 1.92）⇒ **保留文档原版 centroid**。
3. **0 是合法速度，不得因为速度算出来是 0 就换源**（本轮真 bug，旧实现已废）：旧代码"历史速度为 0 ⇒ 用检测流速度兜底"把目标静止的合法 0 换成**跨目标切换**的脏速度（−2.857 px/帧）× Δ=2 ⇒ 5.71 px 假位移 ⇒ **Gate 3b 一直 FAIL**。**检测流速度只能在历史速度取不到时兜底**。
4. **硬拉回触发的前提就是"快跟踪器已锁在杂波上"** ⇒ 此刻它的历史速度**正是杂波的速度** ⇒ 拿它投影只会把刚拉回的目标**再甩出去**（实测 65.0% 的硬拉回落在 ROI 半窗外，硬拉回后第 1 帧 inbox 命中率只有 75.0%，不投影是 84.0%）。
5. **规格文档自身不一致**（§二.3 散文 vs §三 伪代码）：散文说硬拉回要"叠加上历史运动速度 v×Δ"，伪代码却写 `curr_pos = np.array(det_xy)`（不投影）。**实测证明 §三 伪代码才对** ⇒ 代码改成三档可切换、默认 `none`。
6. **初始化分支也必须跟着不投影**：`_project_to_now` 若无条件外推，8 帧前的检测框会被放大成假位移（臂 3 44.60%→47.79%、alpha 45.20%→48.01%）。
7. **抖动指标必须拆分归因**：`max(Δv)` 几乎总被状态机切换/冷启动吃掉 ⇒ 必须分 `steady` / `transition` / `hard_reinit`。
8. **det_hz 假扫描**：10/12.5/15 Hz 在 25 Hz 相机上都 round 成 stride=2 ⇒ 只能扫 **25 / 12.5 / 8.33 Hz**，并报 `det_hz_effective`。
9. **GT 必须按实际跑过的帧裁剪**：否则命中率分母是整段序列、分子只有跑过的那几帧，口径直接失真（本轮踩过一次，400 帧试跑时覆盖率显示 3.7%）。
10. **`history.overwrite()` 必须同步 `_last_index/_last_xy`**，否则下一次 `push` 会拿"覆写前的旧位置"去算速度。
11. **退回重推演的两个隐含前提**（本轮踩坑）：① 锚点帧 f 的历史位置必须存在（否则无法验证锚点 ⇒ 按设计弃权 `no_history_for_anchor`）；② 重推结果必须**回写历史**，否则后续"同刻对账"仍拿旧的前向轨迹做基准。
12. **`Detection` 是 frozen dataclass**，测试里不能改字段，要构造新的。
13. **快核自校正会掩盖融合效果**：测"残差融合/重推演是否生效"必须用**冻住的快核**，否则快核自己就爬回真值了。
14. **覆盖率口径**：分子必须只算"目标存在的帧上有输出"的帧；用"全部有输出帧 / GT 帧"会**按臂高估 1.7~3.6 pp**（本轮修正，见 §3）。
15. **锚点密度是混淆变量**：臂 1（det_hz=25）与臂 2/臂 3（det_hz=12.5）**不能直接比**；必须加同锚点密度的对照臂（本轮补）。
16. **Wilson CI 不能当等价性证据**：CI 的独立性假设在连续帧上不成立 ⇒ 只能用 McNemar 配对检验下结论（本轮修正）。
17. **规格判据要有适用对象**：臂 3 的 `replay` 整段重定位是**设计内大跳变**，smooth 桶为空 ⇒ 判据对它无定义，不能默认"通过"（本轮修正）。
18. **"p ≥ 0.05"不能写成"打平/等效"**：只能说"本样本量下分辨不出"（臂 3 vs alpha 全 GT 帧 p=0.416 就是这一类，本轮已按此写）。

## 15. 下一步（按优先级）

1. **重定义或重参数化规格判据 1**：α=0.4 / gating=12 px 下 α·e ≤ 4.8 px > 2 px

   （1,988 帧里只拿到 44 hits，臂 1 拿到 140）；要么把臂 3 的弃权率压下来（17.71%），
   要么在验收里**同时报存活窗口命中率**（臂 3 55.41% vs 臂 1 49.06%），别再只看 headline。
3. **换序列复核**：龙泉山 24 条序列里挑**目标更慢**的（单帧位移 p90 < 2 px）重跑——本序列 3.83% 的帧超出 ROI 半窗，是"退回重推演失效"的直接原因。**这是最该先做的事**：先证明方案在**前提成立**的序列上确实有效，再谈优化。
4. **把检测频率降档**：det_hz 12.5 → 8.33 Hz（Δ 帧数不变但目标位移不变，无效）或**降低 Δ**（Δ=4 ⇒ Δ 帧位移减半）——Δ 直接决定重推演能否跑通。
5. **快核提精度**：单步 p50 2.22 px 是当前天花板的主因。方向：成簇目标的**本体提取**（去掉拖尾）而不是整块质心。
6. **臂 3 的弃权兜底**：已实现为消融臂（`replay_fallback="hard"`），headline 只带来 +0.05 个点（47.79%→47.84%）、存活窗口 +0.48 个点——**不是瓶颈**，别再花时间。
7. **板卡移植的延时预算**：臂 3 的 Python 实现 p99 = 1.390 ms 已超 1 ms；上板后重推演要并行/降采样，否则伺服预算不成立。

9. **把"不投影"也纳入移植清单**：C++ / 板卡端（见 `manu/tracking/README.md` 的易丢语义清单）一旦漏掉

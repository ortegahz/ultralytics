### 54.2 ⚠️ 核心发现：trial_0080 现成的 8 序列缓存**不可复用**

`trial_0080/gate/epoch3/ms_cache/` 里已有 8 个序列的多尺度热图缓存，权重正是 `epoch3.pt`，
看起来"特征已算好可以直接用"，但**特征源语义与冻结基线不同**，并入会让结果失去可比性。

| 缓存 | 权重 | 特征源 | 特征语义 | 覆盖 |
|:--|:--|:--|:--|:--|
| `runs/ms_cache_nop0/`（**冻结基线**） | `runs/optuna_p0_nas/trial_0474/weights/best.pt` | `longquanshan_ir_gmc_median/images/train` | **FPV 仿射连乘** | 24 序列 / 165,223 帧 |

同一 `frames_ir_jpg` 根目录），而是 **GMC 拟合语义不同**：

official 是逐 lag 直接拟合 `H = compute_affine(im_h, im_curr)`（同文件 `:220-233`）。
逐像素差 **26~70/255**，不是编码噪声。

**代码分歧点**：`manu/data/build_longquan_ft_dataset.py:180`（fpv 分支 `_compose_chain` 左乘累积）vs `:220-233`（official 分支）。

**并入会造成的四重偏差**：
1. 输入特征语义不一致（official vs FPV，逐像素差 26~70/255）；
2. "全量 24 序列 F1" 变成两个分布的加权平均，无法与 87.070% / 90.605% 做差值归因；
3. 权重也不同（`epoch3.pt` vs 基线的 `trial_0474/best.pt`），变量不隔离；
4. **不可审计**：`multiscale_heatmap_cache.py:437-462` 的 meta 只记 `source=features|raw_frames` 与
   `hm_weights`，**不记特征源绝对路径**，混装后无法从 pkl 自证来源。

### 54.8.1 ⚠️ 等待 GPU 的两个坑（已修，值得记）

本轮等 GPU 花了约 1 小时，暴露两个**判据级缺陷**——两者都会让"GPU 早已空闲但脚本仍在空转"：

| # | 坑 | 现象 | 修法 |
|:--|:--|:--|:--|
| 1 | `pgrep -f "optuna_mix_ratio_search.py"` **匹配到监控 shell 自身** | 监控命令的命令行里含该字样 ⇒ `pgrep` 把自己也数进去 ⇒ `search_procs` 永远 ≥1 | 改用 `ps -eo pid,cmd \| grep -E "python.*optuna_mix_ratio_search" \| grep -v grep`（只认**真正的 python 进程**） |
| 2 | `NPROC=$(... \| grep -c . \|\| echo 0)` —— `grep -c` 无匹配时 **exit 1** | `\|\| echo 0` 又补一个 0 ⇒ 变量变成 `"0\n0"` ⇒ `[ "$NPROC" = "0" ]` 永远不成立 | 计数一律用 `wc -l \| tr -d ' '`，不用 `grep -c` |

修好后的判据（两个条件同时成立才放行）：

```bash
NPROC=$(nvidia-smi --query-compute-apps=pid --format=csv,noheader 2>/dev/null | wc -l | tr -d ' ')
NSEARCH=$(ps -eo pid,cmd --no-headers 2>/dev/null \
          | grep -E "python.*optuna_mix_ratio_search" | grep -v grep | wc -l | tr -d ' ')
if [ "$NPROC" = "0" ] && [ "$NSEARCH" = "0" ]; then break; fi
```

**教训**："等资源"的判据本身要按**被等的那个东西的精确形态**写，不能用模糊的模式匹配；
自监控脚本的命令行还要避开自己的判据字符串。

### 54.8.2 后台常驻的正确启动姿势

`nohup ... &` 经 `ssh` 启动时，若同一会话里随后执行 `pkill -f <同名>`，会把**刚起的实例一起杀掉**
（本轮踩到：新实例刚起即被自身清理命令误杀，日志停在启动那一刻）。
⇒ 启动用 `setsid nohup ... < /dev/null &`（完全脱离会话），
且清理旧实例要在**启动新实例之前**做完，二者不要出现在同一条命令里。

# sniper_gate — no-GMC 高精狙击档位（`trial_0049` + 判别门）

> **受控交付件** · schema `sniper_gate_params/1.1` · package `sniper_gate_trial_0049`
> 门默认 **关闭**（`enabled: false`），与仓库内其它候选门参数文件的保守默认一致。
> **能量门阈值 = `sums ≥ 14.5`**（0.5 步长细扫定出的真峰）。

## 1. 这是什么 / 不是什么

**是什么**：no-GMC 线上「高精狙击档位」的受控配置包 —— `trial_0049@epoch20` 底模 + 判别门
（area / sums / tag 三元谓词）。它把**在样本外仍然成立**的那个工作点冻结下来，配一份**可复现的回归测试桩**
和一份**板端 C++ 部署契约**。

**不是什么**：

| 不是 | 说明 |
|:--|:--|
| 主装 | **主装仍是 `cs_t0043`**（Model Soup 产物）。本包是**进阶档**，不是主装。 |
| 新检测器 / 新推理路径 | 门是纯后处理，不碰 GPU、不重建缓存、不改任何冻结阈值。 |
| 阈值改动 | `th_base`（0.30）与 `dedup_radius`（768.0）与冻结交付配置**逐字相同**，门不改它们。 |
| 门禁红线重定义 | 本包**不包含** `reference_frame.json`，也**不重定义**任何门禁红线语义；T1/T2/T3 阈值仍归上游三轨门禁链所有，本包只**引用并记录实测值**。 |

**与通用交付默认档的区别（务必分清）**：

| 档位 | `sum_value` | 适用 | 出处 |
|:--|--:|:--|:--|
| 通用交付默认档 | **16.0** | 两条臂都安全（T2 硬门留足余量） | `manu/evaluation/system_sota_longquan_candgate_params.json` |
| **本包（高精狙击档）** | **14.5** | **`trial_0049` 单臂最优（在冻结的 `th_base=0.30` 下）** | 本包 |

`14.5` 是 `trial_0049` 的 T3 最优点（`16.0` 会让本臂 T3 掉约 0.0312 pp，而 `cs_t0008p2` 在 `16.0` 反而更好）。
**两个档位是按臂分别选定的，不可互换。**

⚠️ **「最优」是按臂 + 按冻结阈值而言的**，不是全局无条件的：
- 按臂：`trial_0049` 最优在 **14.5**；`cs_t0043` 最优在 **14.0**；`cs_t0008p2` 最优在 **17.5**（三者不可共用一个常数）。
- 按阈值：下表是 `th_base × sum_value` 联合扫描（372 行，350.5 s，样本外 `exclude-primary`）里**未被采纳**的近邻档 ——
  `th_base=0.31` + `sums=14.5` + `post` 的 T3 = **0.911208299**（FP 170，T2 0.999009/FP30），
  比本包（`th=0.30`）高 **+0.0112 pp**、FP 少 6、T2 余量更厚。
  **不予采纳的理由**：① 增益是 **0.011 pp（净 1~2 个检测）量级**，在 52 点二维网格上属**评估集拟合噪声**，
  而 `sums=14.5` 的改档是在**已冻结的一维门常数**上做细化、且落在 14.5~15.5 平台上；
  ② 改 `th_base` = 改**冻结的检测阈值**，要重开整条审计链（交付参数文件、冻结记录、逐轨阈值口径），
  与「交付形态一旦裁定即冻结」冲突；
  ⇒ **本包维持 `th_base=0.30` + `sums=14.5`**，此条仅作**已测未采纳**的留档，供复核者查阅。

## 3. 门语义逐条解释

门的实现见 `manu/evaluation/candidate_gate.py` 的 `CandidateGate.mask`。对**每个候选**（一个连通域），
三个条件**全部成立**才保留：

| # | 字段 | 判据 | 本包取值 | 精确语义 |
|:--|:--|:--|:--|:--|
| 1 | `area` | `area >= area_min` | `area_min = 1` | 连通域像素数（该候选自身尺度栅格上）。`area=0` 被拒。 |
| 2 | `sums` | `sums >= sum_value` | `sum_value = 14.5`，`sum_mode="abs"` | 连通域内热力图积分（"能量"）。**绝对**地板：与数据集分位总体无关。 |
| 3 | `tag` | `tag ∈ tag_allow` | `tag_allow = [0,1,2]` | 候选来源尺度：`0`=原生 640、`1`=160、`2`=80。烘焙融合行 `255` 不在白名单内，被拒。 |

**`th_base` 与 `gate_stage`**：

* **`th_base = 0.30`** 是**冻结的全局分数阈值**，门**完全不管**它 —— 门谓词的入参只有 `(area, sums, tag)`，
  没有分数。因此门**不可能**放松或收紧 `th_base`。`th_base` 在门之后由上游链路用于**选帧/计分**。
* **`gate_stage = "post"`**：门作用在**跨尺度去重之后**的合并候选池上（`post`），
  而不是去重之前（`pre`）。板端必须复刻这个**顺序**，否则去重的结果会不同。

**dtype 语义（板端必须对齐）**：`area` 是 `int32`，`sums` 是 `float32`，`tag` 是 `int16`。
`sums` 的比较是**在 float32 下**做的：`13.9999999` 在 float32 里就等于 `14.0`，因此**被拒绝**（低于 14.5）；
同理落在 `14.5` 附近、但因 float32 舍入恰好等于 `14.5f` 的候选也会**被接受**。
`sums >= 14.5` 是**闭区间**（`>=`，不是 `>`）。

### 3.1 `sums ≥ 14.5` 的浮点敏感性（板端必读）

`sums` 是候选连通域上热图强度的**浮点累加**。板端的累加顺序 / 精度与服务器不同 ⇒
个别候选的 `sums` 可能落在 `14.5` 附近而**翻转**（跨过 / 掉下阈值）。契约必须为此留余量：

* **服务器参考实现**：连通域积分在 **float64** 下累加（`numpy.bincount` + float64 权重，
  见 `manu/evaluation/peak_attributes.py`），再以 **float32** 存进缓存（`manu/data/multiscale_heatmap_cache.py`）；
  门比较的是**存下来的 float32 值**。板端应对齐这一"float64 累加 → float32 存储"的语义。
* **实测曲线斜率**（0.5 步长细扫，post 档，11..17）：

  | 区间 | \|ΔT3 F1\| | 折合 |
  |:--|--:|--:|
  | 相邻 0.5 步长**全局最大**（13.5 → 14.0） | `0.000592` | 0.0592 pp |
  | 平台邻域内最大（15.5 → 16.0） | `0.000222` | 0.0222 pp |
  | 交付点 ±0.25 阈值扰动（线性插值） | **≤ `0.000121`** | **≤ 0.0121 pp** |

  即：**±0.25 的阈值扰动 ⇒ T3 变化 ≲0.0002（0.02 pp）**，远小于分隔各档位的间距，
  **不改变档位排序与交付结论**。
* **平台安全性**：交付点落在 **14.5~15.5 平台**上 ——
  `14.5 → 0.911096427`、`15.0 → 0.910940440`、`15.5 → 0.911005953`，
  平台内极差 `0.000156`（0.0156 pp）。即使板端实现有微小差异、落到 `15.0` 或 `15.5`，
  也**不会掉出平台**，T3 仍在 `0.9109` 以上、相对 RC2 仍有 **+1.32 pp** 以上。
* **最坏情形（如实核算）**：若有效阈值一路漂到 `sums ≥ 16`，T3 F1 为 **`0.910784263830220`** ——
  这比被取代的旧档 `14.0`（`0.910854878854066`）**低 0.0071 pp**（**不是更高**），
  但**仍然比 RC2（0.897693732）高 +1.3091 pp**，且**仍然高于 0.91** ⇒ 交付结论不变。
* **契约建议**：板端累加用 **float32 + 固定累加顺序**（与服务器 `numpy.float32` 存储对齐），
  并把阈值实现为 `sums >= 14.5f`，同时保留一个**可配置的 ±0.1 容差**，
  使"近阈值候选翻转"不会静默改变档位。

## 4. 样本外性来源

**这是构造保证，不是测出来的性质。**

`sum_mode="abs"` 的阈值是**常数 14.5**：它不依赖任何数据集分布、不依赖分位总体、不需要逐 tag 阈值表。
因此它**可以**在臂之间、序列之间迁移 —— 这是由"常数阈值"这个形式本身推出来的。

**反例（同一套代码里的 `tagq` 形式就没有这个性质）**：`sum_mode="tagq"` 的阈值是能量总体的一个分位，
它的取值**内含**所选总体的信息。样本内选出的最优分位（`trial_0049` 选 `tagq q0.2`）到样本外**不成立**，
并且会**打破 T2 硬门**（该配置 T3 −6.2527 pp，T2 硬门 FAIL），因此被废弃。
所以：分位总体门**没有**样本外性；绝对能量门**有**。

> 注意口径：门**档位（14.5 这个数）本身**是在评测池上挑的，因此整套证据仍属**探索性**。
> 样本外性指的是**阈值形式**不携带总体标定，而不是"档位没被挑过"。所以本包**出厂关闭**。
>
> 另注：`tagq` 族的最高 T3（`0.910940440`）虽已被本档的 `0.911096427` 超过，
> 但**"超过它"不等于"可以采用它"** —— 分位门没有上面的构造保证，其样本内最优已被判定样本外失效。

## 5. 板端 C++ 部署契约

> 本节不依赖 Python，可直接照此实现。语义与 `manu/evaluation/candidate_gate.py` 的 `CandidateGate.mask` **逐条一致**。

### 5.1 输入字段（每个候选）

| 字段 | 类型 | 含义 | 来源 |
|:--|:--|:--|:--|
| `area` | `int32` | 连通域像素数（该候选自身尺度栅格） | 多尺度热力图缓存 |
| `sums` | `float32` | 连通域内热力图积分（能量） | 同上 |
| `tag` | `int16` | 来源尺度：`0`=640，`1`=160，`2`=80，`255`=烘焙融合行 | 同上 |

门**不接受分数**：分数阈值 `th_base` 由下游按 `scores >= th_base` 另行处理，门不碰。

### 5.2 判定表

| 条件 | 表达式（精确） | `>=`/`<` 语义 |
|:--|:--|:--|
| 面积 | `area >= 1` | **闭**。`area == 1` 通过；`area == 0` 拒绝。 |
| 能量 | `sums >= 14.5f` | **闭**。`sums == 14.5f` 通过；`13.9999999f`（float32 下即 `14.0f`）拒绝。 |
| 尺度 | `tag == 0 \|\| tag == 1 \|\| tag == 2` | 等值白名单。`tag == 3`、`tag == 255` 拒绝。 |

三者**逻辑与**。任一不满足 → 该候选被丢弃。

### 5.3 判定顺序（`gate_stage = "post"`）

```
S1  取多尺度缓存的三行（tag = 0/1/2）；按分数降序做跨尺度贪心去重（radius = dedup_radius = 768.0 原生像素）
S2  对 S1 的**存活**候选逐个施加本门（post 阶段：去重之后、分数阈值之前）
S3  存活候选按原顺序（分数降序）保留；被拒候选丢弃，帧集合不变（整帧被拒 = 该帧空候选列表）
S4  下游再按 scores >= th_base(=0.30) 选检测（门不参与这一步）
```

**板端注意**：

* `post` 意味着门在**去重之后**。若板端把门放到去重之前（`pre`），被拒候选就不会参与去重占位，
  结果会与 Python 侧不同。
* 去重先于门，所以门的三个条件作用于**去重后**的候选。
* 门**不改变帧集合**：某帧所有候选被拒时，该帧仍在帧列表里，只是候选为空。

### 5.4 最小 C++ 片段（与 Python 逐条等价）

```cpp
// gate_params: area_min=1, sum_value=14.5f, tag_allow={0,1,2}
// Optional tolerance: compare sums >= (14.5f - tol) with tol defaulting to 0.1f, so that a
// near-threshold candidate flip caused by a different float accumulation order on the board
// cannot silently change the tier (see section 3.1).
inline bool gate_keep(int32_t area, float sums, int16_t tag, float tol = 0.1f) {
    if (!(area >= 1))            return false;   // area_min = 1，闭区间
    if (!(sums >= 14.5f - tol))  return false;   // 绝对能量地板，闭区间，float32 比较
    if (tag != 0 && tag != 1 && tag != 2) return false;  // tag 白名单，255(融合行) 被拒
    return true;
}
// 调用顺序：dedup(radius=768.0) -> 对存活候选 gate_keep() -> 下游 scores >= 0.30
```

## 7. 代价与短板（不省略）

1. **需要板端 C++ 部署 + 契约认证。** 本包是决策层后处理，必须在板端复刻 §5 的判定表与**判定顺序**
   （`post`：去重之后、分数阈值之前）。判定语义错一位（`>` vs `>=`、`float64` vs `float32`、门放到去重之前）
   都会让板端与离线数字对不上。
2. **底模是单种子单模型（epoch20，尖锐极小值）。** 极冷/极热等边缘未知工况的抗扰动**略逊于 Model Soup 产物**。
   `cs_t0043` 是主装，本包是进阶档 —— 本包**不是**主装。
3. **T1 硬门不过线（−0.4941 pp）。** 这是本包**必须写明**的事实：本档位在 T1（`trial_0049` 自身）上是
   `0.8909556600604635` < 红线 `0.8958967482400269`，差 **−0.4941 pp**，属**否决项**。
   门只在决策层动，**T1 数字不变**（`0.890955660` 照搬未加门的 `gate_report.json`）：
   本包的 K2/K3 扫描只测了 **T2/T3** 两条轨（扫描命令的 `--track` 只列了 t2 与 t3），
   T1 是单帧轨、按自身峰值阈值 `0.25` 单独测量，不走这条决策层链路 ——
   上游 `CANDIDATE_COMPARISON.md` §4 的标题同样写着"**T3 侧唯一真收益；T1 数字不变**"。
   换言之：**T1 的不过线是底模的性质，不是门造成的，门也救不回来。**
4. **随包备验件 `cs_t0008p2` 的角色**：它是**同族的另一条臂**，用途是**对照与备验** ——
   `cs_t0008p2` 是**过 T1 线**的那条（T1 `0.895900516`，`+0.0004` 过线），且其门档位是 `sums≥16`
   （T3 `0.880177210`）。也就是说：**要 T1 过线 → 用 `cs_t0008p2`；要 T3 最高 → 用本包 `trial_0049` + `sums≥14.5`，
   但要接受 T1 不过线**。两者不是同一档位，不可互换（见 §1 的档位表）。
5. **档位是在评测池上挑的**，整套证据仍属**探索性**，因此出厂 `enabled: false`。
6. **阈值是浮点敏感的**（见 §3.1）：`sums` 是浮点累加，板端累加顺序/精度不同会使近阈值候选翻转。
   交付点位于 **14.5~15.5 平台**上，**不会掉出平台**；但若实现有系统性偏差，
   最坏退回 `sums≥16`（T3 `0.910784`）会比旧档 `14.0` **低 0.0071 pp**（仍高于 RC2 +1.3091 pp、仍 > 0.91）。
   因此板端**必须**按 §5.4 用固定累加顺序 + 可配置 ±0.1 容差实现。

# 时域积分与 TBD（检测前跟踪）专题 (Temporal Integration & Track-Before-Detect)

> **版本时间**：2026-09-17
> **定位与使命**：记录"沿轨迹累加多帧证据"这条路线从动机、上界实测、到逐一证伪的完整闭环。回答一个被领导直接追问的核心问题：**"人眼盯着看能认出来，为什么算法不行？"**
> **适用场景**：涉及单帧极限之外的召回突破、难例真值解救、多帧输入设计、或需要向非技术方解释"为什么单帧检测有极限"时必读。

## 一、问题起点：人眼能看见，模型看不见

| 事实 | 实测 |
|---|---|
| 单帧目标强度 | 匹配滤波 Z ≈ **3.3σ** |
| 同帧噪声峰（640×512 全图最大） | **5.40σ**（≈32.7 万像素纯噪声的最大值期望） |
| 结论 | **目标低于搜索门限约 1σ → 单帧不可分** |
| 人眼 | 盯 2~3 秒即可识别 |

**人眼的优势不是单帧灵敏度，而是沿运动轨迹的时间积分。** 用户实测观察确认：单帧能看见亮点，但分不清是噪点还是飞行器；看 2~3 秒有了轨迹信息就容易判断。

## 二、核心事实：目标时间能量完全相干（Oracle 上界，实测）

| N（帧） | signal_mean | noise_std | **SNR** | gain | √N | PD@3σ |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 1 | 3.275 | 0.8416 | **3.89** | 1.00 | 1.00 | 60.6% |

**三条判据同时成立**：
1. `signal_mean` 不衰减（3.275→3.834）→ **目标时间相干**；
2. `noise_std` 严格按 $1/\sqrt{N}$ 收缩（0.8416→0.0979，比值 8.6 ≈ √75=8.66）→ 标准非相干积累；
3. `gain` 紧贴 √N。

**对照序列**（`wg011_03` 5.11→37.89、`DJI_0175_2` 2.85→25.33）行为一致 → 探针可信。

### ⚠️ 重要更正（推翻旧结论）
早期用 **"整数像素对齐 + 取峰值"** 的粗测得到"GT 对齐多帧平均无效（对比度 4.67→4.43，MAD-Z 4.05→3.80）"，据此写过"目标时间不可积 / TBD 期望值低"——**该结论是测量假象，已作废**。
- 原因：2px 目标用整数对齐误差达 25% 尺寸；且"取峰值"对抖动目标天然低估；
- 正确测法：**匹配滤波响应域 + 亚像素双线性采样 + 取均值**。

**因此：单帧无解 ≠ 无解。目标是可检的，瓶颈在"如何在不训练的前提下利用它"。**

## 五、两个必须记住的关键认知

### 1. 悬停目标与静态坏点在"累加"意义下同构
- 坏点：每帧都亮 → "停在 (5,5)"的路径累加 = 真目标累加；
- 悬停目标：停在原地的路径累加 = 同值；
- **推论**：任何以"速度/位移"为判据的抑制手段（如 `vmin`）**必然误伤悬停目标**（记忆里 HC5 正是悬停）。
- **正确判别量是时间上下文（onset / 持久性），而非速度**：坏点全序列一直在；悬停目标中途出现、之后离开。

### 2. 假轨迹的主因是"持久背景结构"，不是随机白噪声
- 随机平滑轨迹 null（`probe_tbd_random_trajectory.py`）实测：
  - `vmax` 从 3.0 收紧到 1.5，`null_std` 与 `null_max` **反而升高**（L=9：0.336→0.437 / 3.328→4.082）；
  - 白噪声模型无法解释（收紧速度应缩小搜索空间、降低极值）；
  - `null_max/σ` 达 7.3~12.2，远超 10⁵ 独立高斯样本的期望 4.8 → **重尾**。
- **解释**：慢轨迹会"锁"在持续亮斑（固定图案噪声 / 静态热结构 / 坏点）上，L 个样本高度相关。
- **对策方向**：持久性抑制（`min_hits`/net-displacement 那套刚性坏点剪枝的思路），**而非速度门槛**。

## 六、速度滤波组特征：HC1 零训练操作级 ROC 验证（2026-09-18）

### 1. 验证脚本与严格口径
- 脚本：`manu/probe_speed_filter_bank.py`，`--mode roc`；本轮仅测试 `wg2022_ir_020_split_03`（HC1）。
- 处理链：原始灰度 DoG+CFAR 响应 → 每个历史帧直接估计到当前帧的 GMC 仿射（不再逐帧矩阵连乘，避免漂移）→ 固定速度组累加 → `max_v A_v` 全图局部峰 → 8px GT 匹配。
- 运行参数：速度 `v=0, 0.5, 1, 2, 3, 4 px/frame`、8 个方向、ROC 窗口 `W=1/3/5/9`、`frame_stride=2`、目标 FAR `0.045/frame`；745 个评测帧、245 个 GT 样本。
- **重要口径**：这是无训练经典滤波器的候选检测 ROC，不是加入神经网络后的最终 Recall；`PD@FAR` 是该特征在操作级虚警约束下的可检测性上界参考。

### 2. HC1 实测结果（FAR≈0.045/frame）

| 方案 | 阈值 | PD / 候选检测率 | 实际 FP/frame | 相对 W=1 |
| :--- | ---: | ---: | ---: | ---: |
| 单帧 DoG+CFAR，W=1 | 8.677 | **0.8%** | 0.046 | 1.0× |
| 速度滤波组，W=3 | 19.614 | **10.6%** | 0.046 | 13.3× |
| **速度滤波组，W=5** | **28.832** | **19.2%** | **0.046** | **24.0×** |
| 速度滤波组，W=9 | 50.575 | **16.3%** | 0.046 | 20.4× |

- W=5 是当前盲搜匀速模型的最佳工作窗；在相同 FAR 下比单帧匹配滤波从 0.8% 提升到 19.2%，但**不能直接等同于模型 Recall 从 7.6% 提升到 19.2%**。
- 与当前 HC1 系统 Recall 7.6%相比，W=5 的经典特征检测上界约为 2.5 倍；能否被训练后的网络实际利用，必须另做 Twin A/B。
- 这是一个**有价值但未突破的正向信号**：速度滤波组确实改善了 HC1 的低信噪可检测性，但仍只能覆盖约五分之一 GT，距离 50% 没有实测依据。

### 3. 当前结论与边界
1. **速度滤波组不应再按长时 √N 路线理解**：HC1 的 W=3→5 有效，W=9 开始回落；真实慢速绕圈轨迹无法被长窗匀速直线假设持续覆盖。
2. `PD@FAR` 必须在同一 FP/frame 下比较；此前 `PD@FPR99.9%` 的 60.8% 是像素采样口径，约对应每帧数百个背景峰，不能当作工程 Recall。
3. 该 ROC 仍使用 `frame_stride=2` 与经典匹配滤波器，下一步若继续，只需做一次 `frame_stride=1` W=3/5 复核；不应立即展开速度 NAS 或多阶段周末调度。
4. 只有在 W=5 的 stride=1 结果稳定后，才准入一个最小 Twin A/B：A=原 3 通道，B=原 3 通道+W=5 速度特征；重点看 HC1 Recall、FP/frame 与全盘零回退。

### 4. 速度滤波组定义（保留原方案）
对每个速度假设 $v=(v_x,v_y)$，把过去 W 帧的匹配滤波响应按速度平移后累加：

$$A_v(x,y) = \frac{1}{W}\sum_{i=0}^{W-1} Z_{t-i}\left(x-i\,v_x,\ y-i\,v_y\right)$$

一组速度假设作为输入通道，而不是新增独立检测器；若进入训练，必须遵守 Twin A/B 与官方 DataLoader 零漂移协议。

### 5. 方案动机与历史边界（保留）

**动机**：仲裁问题的唯一原则性解法是**不要两个检测器**，而是把"运动对齐的时序累加"做成**输入特征**，让模型在**同一次决策**里使用它。

| 维度 | TBD 检测器 | 速度滤波特征 |
| :--- | :--- | :--- |
| 仲裁问题 | 有（无解） | **无**（单决策者） |
| 测试轨迹数 | DP 穷举所有弯曲路径 → 虚警膨胀大 | 只测固定速度直线 → 膨胀小 |
| 静态特征 vs 动目标 | 无法区分 | **天然可分**（坏点对所有速度都高，动目标只对匹配速度高） |
| 决策 | 手调阈值 | 模型自己学 |

相对历史失败：时序 Tubelet（空间未对齐致增益归零）与跨窗口时序卷积 NAS（58 组触及天花板）都是"让网络自学对齐"，而速度滤波是**显式给出对齐后的证据**。

**仍未消除的风险（必须诚实）**：
1. **负样本霸权**：无论"加输入通道（需 Twin A/B 重训）"还是"零初始化侧支"，都撞上历史失败的那道坎（形态学侧支门控退化至 −0.0005、跨窗口 NAS 卡死 0.9064）；
2. **长尾稀有**：该类目标在 43,008 训练帧中占比极低，重训后模型仍可能忽略该特征；
3. **悬停场景**：$v=0$ 滤波器对悬停目标有响应，但坏点也响应 → 仍需持久性/onset 线索。

## 七、结论与待决

### 已确认
1. **单帧范式下不可分**（3.3σ vs 噪声峰 5.4σ）——这是**单帧检测边界**，非传感器物理极限；
2. **时间能量完全相干**（Oracle 15 帧→15.4σ），信息充足；
3. **固定匀速速度滤波组只能部分利用时间能量**：HC1 在 W=5 达到操作级 PD=19.2%，W=9 回落到16.3%，说明真实慢速绕圈轨迹的直线相干窗口较短；
4. **以速度/位移做抑制会误伤悬停目标**（与坏点同构）；
5. **速度滤波组的操作级 ROC 已完成，但尚未进行模型注入训练**：19.2% 是经典候选检测上界参考，不是训练后 Recall 承诺。

### 三条可选路径（按推荐度）
| 路径 | 内容 | 成本/风险 |
| :--- | :--- | :--- |
| **A. 收口（当前默认）** | 保留速度滤波实验为正向证据，不动生产系统 | 零回归风险；HC1 仅占全集 2%，全解 F1 增益有限 |
| **B. 一次性最小 Twin A/B** | 先以 `frame_stride=1` 复核 W=3/5；若稳定，仅做 A=原3通道、B=原3通道+W=5 速度特征 | 中等成本；必须同时看 HC1 Recall、FP/frame、全盘零回退 |
| **C. 扩展速度搜索/长窗重训** | 多速度 NAS、弯曲轨迹、长窗组合 | 不推荐；长窗已回落，且历史"改模型"0胜7负 |

### 汇报口径（可直接用）
> 该目标为 **2×2 像素、仅高出背景 9 个灰度级**，**总积分能量为全部 23 条序列中最低**（比次低低 2.7 倍）。单帧匹配滤波仅得 ~3.3σ，**低于同帧噪声最大起伏 5.40σ**，故**单帧检测范式**下不可分。而沿真实轨迹的亚像素积分证明其时间能量完全相干（**15 帧达 15.4σ，增益严格符合 √N**）——**信息充足、目标可检**，瓶颈在于当前"先检测后跟踪"架构要求单帧高置信度才能起轨，而该目标仅 2% 帧满足。**能力缺口在检测范式，不在传感器极限。**

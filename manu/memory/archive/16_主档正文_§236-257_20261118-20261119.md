### 一、🔴🔴 根因：`nano_search.py` 的 `_merge_disk_ledger` 是「整臂覆盖」
- **现场**：`save_ledger()` 前的 merge 逻辑会把**磁盘上的整条臂**直接盖到内存臂上
  （只对「内存里没有的臂」做合并也还不够——只要内存臂存在但**磁盘臂更新**，就会用磁盘的旧值覆盖内存的新值）。
- **为什么会炸**：`flock` **只保护了「写盘」这一个临界区**，**没有保护「读→改→写」的整个事务**。
  ⇒ 两个进程（波次 / 门禁 / 守望 / 守卫）各自「load → 改一个字段 → save」时，后写者会把先写者的**其它字段**一起回滚。

```python
fusion_salvage_mask = is_sky & (sc >= th_salvage) & (sc < th_base)
```

⇒ **v3 = 取消了一切天空/地面之分**，三处同时改变：
1. **阈值层**：`~is_sky` 恒空 ⇒ `th_ground=0.26` 变成**死参数**，全帧只用 `th_base=0.48`。
2. **分层层**：地面区 0.30 分的检测从「Tier 1 可以起航迹」降级成「Tier 2 只能挂已有航迹」⇒ **凭空多出来的假航迹被掐掉**
   ⇒ 这就是 `002251` 掉 FP 的真正机制。
3. **smoother/tracker 层**：`sky_ratio` 还决定**天空感知的刚性剪枝**和 **hover 豁免**（`y < sky_ratio·H` 的静态目标永不清除）⇒ v3 下**整幅画面**都受豁免。

⚠️ **`th_deep` 在三版里都是死的**：`th_deep=0.0`，而代码是 `if th_deep > 0.0:` 才启用 deep 弱带 ⇒ 改它不会有任何效果。

板卡 C++ 侧**已经完整实现了分区**（`rk3588_app_base/mosaic_sdk/src/npu/mosaic_track_fusion.cpp:468-470`：`is_sky ? (s>=th_base) : (s>=th_ground)`），
所以 **v3 不需要任何移植改动**；反过来 th045/v2 依赖分区，且 `sky_boundary` 在 C++ 端是 float32、Python 端是 float64 比较，

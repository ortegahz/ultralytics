### 七、新增铁律（写进 `rules.md`）

- **铁律三十二：任何后台长期进程必须挂在「长驻父进程」下启动，不能用 `ssh 'cmd &'` / `nohup cmd &` 这种父进程会立刻退出的方式。**
  事故：`day_supervisor_d1.sh` 内有「soup3 孤儿收割器」——
  `ps -eo pid,ppid,args | grep "night_soup3[.]py" | awk '$2==1{print $1}'` 会 **SIGKILL 掉 PPID==1 的 `night_soup3.py`**。
  本轮 `nohup night_soup3.py &` 连起两次都在**打印完配方后静默消失、无 traceback、无 OOM 记录**（实为被收割器 kill）。
  正解：写 wrapper 脚本**前台等待** python（**不能 `exec`**），再 `setsid bash wrapper.sh &` 启动：
  ① wrapper 的 argv 不含 `night_soup3.py` ⇒ 不会被收割器 grep 命中；
  ② python 的 PPID = wrapper PID ≠ 1 ⇒ 不会被收割。
  参考实例：`/tmp/run_soup.sh`（参数：gpu / sid_base / sid_span / max_gates / recipe_file / logname）。
  存活判别：`ps -eo pid,ppid,etime,args` 看到 python 的 **ppid 指向 wrapper** 才算活着。
- **铁律三十三：汤（模型汤 / 权重平均）只能在同一盆地内混合；跨盆地混合会让 nano 崩塌，且崩塌幅度远超线性外推（本轮实测 −21.4 阶 vs 线性预测 −0.5 阶）。**
  ⇒ 任何「加一个新配料提某一轴」的方案，先确认新配料与母汤**同盆地**（同 init / 同配方格 / 同 SWA 家族），
  否则**直接判死**，不要浪费机时。
  ⇒ **不要用线性外推（"w·Δ"）判断汤的收益**：跨盆地时汤的响应是**强非线性且负**的。

### 四、🟢 停机方法论（已沉淀为铁律四十二 / 四十三）

**🔴 坑 1 —— 父进程被杀 ⇒ 子进程被 init 收养 ⇒ 只杀一层不够**
`night_soupdonor_axis.py`（父）被杀后，其子 `optuna_mix_ratio_search.py`（band C 训练 worker，9 个 dataloader 子进程）**被 init 收养继续跑**；`night_soup_batch.py` 被杀后其 `auto_epoch_gate_check.py` + `multiscale_heatmap_cache.py` 同样存活 ⇒ 必须**扫多轮**。

**🔴 坑 2 —— `sshd: huangzhe@notty` 会误杀自己**
程序化 SSH（`ssh host 'cmd'`）在服务器端也是 `sshd: huangzhe@notty` ⇒ 若按「杀所有 notty」来清理，**会把自己的会话也杀掉** ⇒ 脚本执行到一半夭折（本次实测踩到，表现为清理日志中途截断）。
⇒ **正解：祖先链排除法** —— 从 `os.getpid()` 沿 `PPID` 上溯，把整条祖先链列入**保留集合**，只杀集合外的。

**🔴 坑 3 —— 模式匹配会自匹配**
用 `grep -E "anaconda3/envs/uav|..."` 统计残留时，**监控命令自身**的 argv 也会命中（远程 shell 用的是 `uav` 环境的 python）⇒ 计数会随机跳动 ⇒ 终判必须**用不依赖该环境的命令**（如 `bash` + `ps`）复核。

**🔴 坑 4 —— 守望层不杀 ⇒ 杀了会被拉起**
`heartbeat.sh`（每 2 min）+ `day_supervisor_d1.sh` + `nano_watchdog.sh` 会在下一轮**自动复活**训练轴/门禁通道 ⇒ 停机必须**先杀监督层**。

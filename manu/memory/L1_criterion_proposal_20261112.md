## 3. 🆕 「位级差异到底有多大」——本轮新量化（2026-11-12，host 侧复算）

用官方校验器的同一对产物（`regress/old_golden/` 旧板 OpenCV 4.10 vs `regress/full/` 新板 OpenCV 4.6），
逐帧逐检出做坐标级比对（检出按 `(类别, 最近中心)` 配对）：

| 量 | 实测 |
|:--|:--|
| 特征 md5 逐位相同 | **2358 / 11808 = 19.97%**（与官方校验器一致） |
| 检测载荷逐字节相同 | **2840 / 11808 = 24.05%**（与官方校验器一致） |
| 每帧最大坐标差（检出数相同的 11742 帧） | **中位数 0.0000 px**；p95 **0.1096 px**；p99 **0.3091 px** |
| 坐标差 ≤ 0.1 px 的帧占比 | **94.17%** |
| 坐标差 ≤ 0.5 px 的帧占比 | **99.48%** |
| 检出数发生变化的帧 | **66 / 11808 = 0.56%**（差异帧多出的都是阈值附近的极小目标，score ≈ 0.06 量级） |

不是「精度退化」**。这正是 §2 根因②（OpenCV 次版本）的典型表现。

## 4. 三个候选判据

### 方案甲（推荐，**0 成本，立即可执行**）

> **「与基线同量级（|ΔF1| ≤ 1.6e-4）且新库不低于旧库」**

- 本轮新库两条均**优于**旧库：一致率 20.0% > 18.4%；|ΔF1| 1.03e-4 < 1.61e-4。
- 与既有裁定（`memory_compact.md`「交付口径已裁定：F1 宏观一致就可以」）**同口径**。
- 缺点：**不是位级判据**，只是「不掉精度」的判据。

### 方案乙（L2 重建新板 golden，**45 min**）—— ✅ **2026-11-12 已实测兑现**

> 在**当前新板**上用 `rknn_mosaic_e2e` 重建一份参照，此后「md5 全量匹配」重新可达、可作回归守卫。

- 状态：**2026-11-12 08:53 启动、09:46 跑完（52 min，3.78 fps）**；09:51 官方校验器 **VERDICT PASS**（见 §6）。
- 实测：**共同帧 11806 ⇒ md5 逐位 100%、检测载荷逐字节 100%**；官方 ΔF1 = **+0.000000**（TP/FP/FN/R/P/F1 全等）。
- 差异只剩**帧集合边界**：e2e 路径跳 **000001/000002**，异步 push-all 路径跳 **000199/000241** ——
  **两边各跳 2 帧、位置不同**（引擎调度时序决定）⇒ 裁到交集后逐位全等。
- 局限：**只对「同一块板 + 同一套库」有效**；板卡再换一次或库再动一次，又要重建。

### 方案丙（🆕 本提案认为**最完整**，在甲/乙之上叠加，不替代它们）

把判据**拆成两层**，各自回答不同的问题：

| 层 | 判据 | 回答的问题 | 依赖 |
|:--|:--|:--|:--|
| **L-回归**（同环境守卫） | 新板 golden vs 异步路径：**共同帧 md5 逐位 100%**（允许 ≤2 帧引擎跳过）+ ΔF1 ≥ 0 | 「我的改动有没有动数值？」 | 方案乙 |
| **L-认证**（跨环境对齐） | **离散决策等价**（检出数变化率 ≤ 1%）+ **坐标容差**（\|Δcx\|,\|Δcy\| ≤ 0.5 px 的帧占比 ≥ 99%）+ ΔF1 ≥ −1e-4 | 「换了板/换了库之后，精度还认吗？」 | 无（用现成产物即可算） |

⇒ **L-认证**这一层可以**立刻**用 §3 的数字判定（0.56% ≤ 1%、99.48% ≥ 99%、ΔF1 = −1.03e-4 ≥ −1e-4 ⇒ **通过**），
且**不依赖任何新实验**、**不依赖特定板卡**。

## 5. 建议写进验收单的最终判据文本

> **第 3 条验收（位级对齐）分层判定：**
> ① **数值中性（必过）**：与认证 golden 的 **ΔF1 ≥ −1.6e-4**，且**不得低于**改动前的库（同口径）。
> ② **同环境位级守卫（换板/换库后重建参照即可恢复）**：新板 golden vs 异步路径的**共同帧 md5 逐位 100%**，
>    允许的例外仅为 opportunistic 引擎的 ≤2 帧跳过（上限 99.983%）。
> ③ **跨环境认证对齐**：离散决策等价（检出数变化率 ≤ 1%）+ 坐标容差（≤0.5 px 的帧占比 ≥ 99%）。
> ④ **禁止**再把「跨物理硬件的 md5 100%」写成验收项 —— 板卡自带 OpenCV 4.6 与认证 golden 的 4.10
>    之间的亚像素差是**不可消除**的（除非重新打包 OpenCV 4.10，与「用板卡自带库」的交付形态冲突）。

### 6.4 结论：L1 判据怎么裁

**方案乙已兑现 ⇒ 「md5 全量匹配」这条强判据今天就可用了**（以新板 golden 为参照）。
但它**只对「同一块板 + 同一套库」有效** —— 板卡再换一次、库再动一次，就得再重建一次参照。
⇒ **最终建议 = 方案乙（同环境位级强判据）+ 方案丙（跨环境容差判据）+ 方案甲（兜底口径）**。

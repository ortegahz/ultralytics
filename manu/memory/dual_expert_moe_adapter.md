## 二、核心架构：解耦式双专家 MoE Adapter（Physics-Guided MoE）

**设计意图**：彻底阻断对底模梯度的逆向污染 —— 放弃端到端全量重训，采用**外挂旁路双专家适配层**。

```
              时空特征输入 [I_t, Diff_t, Median_t]
                            │
        ┌───────────────────┴────────────────────┐
        │   Trial 0474 Backbone (100% 冻结)        │
        └───────────────────┬────────────────────┘
                            │  P0 特征层（已做时空滤波与下采样）
        ┌───────────────────┴────────────────────────────┐
        ▼                                                ▼
【原始单帧 Heatmap 头】(100% 冻结)            【双专家 MoE Adapter】(~30k 参数，轻量微调)
        │                                                │
        ▼                                ┌───────────────┴───────────────┐
  原生预测热图                                       ▼                       ▼
  H_base ∈ [0,1]                    【专家1: Expert_Large】       【专家2: Expert_Suppress】
        │                            (大目标补盲, ~12k)            (地表路灯压制, ~15k)
        │                                   │                            │
        │                            Δ_pos ∈ [0,1] (正向增量)      M_gate ∈ [0,1] (抑制门控)
        │                                   │                            │
        └───────────────┬───────────────────┴────────────────────────────┘
                        ▼
                【确定性物理融合】
   H_final(x,y) = ( H_base(x,y) + Δ_pos(x,y) ) × ( 1 - M_gate(x,y) )
```

### 2.1 两条专家支路

| 专家 | 拓扑 | 参数量 | 输出 | 物理行为 |
| :--- | :--- | ---: | :--- | :--- |
| **Expert_Large**（大目标补盲） | 3×3 Conv(s=1) → BN → ReLU → 1×1 Conv → Sigmoid | ≈ 12k | `Δ_pos ∈ [0,1]` | 在低频弥散的大目标机身区汇聚并重建中心能量，把原本 **0.08~0.15** 的低矮响应峰值拉升到 **0.40+** |
| **Expert_Suppress**（路灯/地表压制） | 3×3 **Dilated Conv(d=2)** → BN → ReLU → 1×1 Conv → Sigmoid | ≈ 15k | `M_gate ∈ [0,1]` | 用扩张卷积捕获双翼路灯对称高亮斑、细长灯杆与建筑刚性边缘的**空间几何指纹**；检出路灯时 `M_gate → 1.0`，使 0.60 的虚警经 `(1−M_gate)` 衰减至 **0.03 ≪ 0.22** |

### 2.2 融合公式的性质

$$H_{\text{final}}(x, y) = \big(H_{\text{base}}(x, y) + \Delta_{\text{pos}}(x, y)\big) \times \big(1 - M_{\text{gate}}(x, y)\big)$$

- **平坦纯天空区**：无地表刚性指纹 ⇒ `M_gate → 0`；无大目标团块 ⇒ `Δ_pos → 0` ⇒ 严格还原 `H_final ≡ H_base`。
- **逃生开关**：推理阶段配置 `--disable-adapter` 直接绕过右支，**100% 恢复底模**。
- 🔴 **实现时必须钉死的口径（否则下游全错）**：融合发生在**抽峰之前**，
  即 `H_final` 替代 `H_base` 进入现有抽峰 / 连通域 / 多尺度融合 / Track 全链路，
  **下游门限 `th_base=0.22`、`th_salvage=0.06`、`th_ground=0.35`、`main_threshold`、`region_threshold` 全部保持不变**。
  若改成「抽峰后再压制」，则 `0.22` 这套已冻结的交付参数口径全部作废，必须重新标定并全量重跑。

## 三、数据治理：三桶切片挖掘（Hard Mining）

**动机**：业务数据「同场景、同设备、同时段采集」高度同质化 ⇒ **拒绝海量盲目堆叠**，
改用**当前 SOTA 模型预测与 GT 的残差**做**片断级**（非帧级）难例提取。

```
        整段业务视频流（按顺序前向运行冻结底模 SOTA）
                          │
   ┌──────────────────────┼──────────────────────┐
   ▼                      ▼                      ▼
【桶1: 硬负样本】      【桶2: 漏检/大目标】     【桶3: 黄金平飞锚点】
  Hard Negatives          Hard Positives           Easy Anchors
  GT 为空 且 峰值≥0.22   GT 存在 且 预测<0.22     峰值≥0.50 且 IoU 良好
  路灯/窗户/反光         近距大目标/机臂          锚定天空弱小表征
        │                      │                      │
        ▼                      ▼                      ▼
   100% 灌入训练          100% 灌入训练           降采样 10% 混入
   专供 Expert_Suppress  专供 Expert_Large      防特征漂移
```

### 3.1 各桶抽取阈值规则

| 桶 | 判定条件 | 切片提取 | Target |
| :--- | :--- | :--- | :--- |
| **硬负样本** | 全图/局部无真实标注（或预测点距最近 GT 中心 **> 15 px**），但底模 `H_base ≥ 0.22` | 含该虚警的连续 **20~50 帧** | 强制全 0 |
| **漏检/大目标** | 人工框有效且 **Box_Area > 100 px²**，但底模框内最大响应 **< 0.22** | 目标出现前后连续帧 | 基于 GT 真实外接矩形的**宽核高斯热图** |
| **黄金锚点** | 目标清晰连续、底模检出良好且无背景虚警 | 每 10 帧抽 1 帧，或只截 200 帧连续稳定段 | GT 高斯热图 |

- **收敛规模**：从数万帧同质视频精简为 **2,000 ~ 3,000 帧**极致纯度高价值切片。

## 四、训练机制与防御性正则

### 4.1 P0 特征离线张量缓存

- 底模 100% 冻结 ⇒ 一次性离线落盘：全量切片跑底模，导出 **P0 特征张量 `feat_p0`（FP16，约 1.3 MB/帧）** + **原始热图 `h_base`**。
- 估算体积：3,000 帧 ≈ **3.9 GiB**；Mini-Golden Val 1,500 帧 ≈ **1.8 GB**；训练脚本启动时全部预加载进内存（RAM）。
- 收益预期：单卡训练吞吐量数千帧/秒，**一个训练周期几分钟**。

### 4.2 强几何数据增强（破解「死记路灯绝对坐标」）

针对同机位、同背景导致模型**背绝对坐标挖坑**的物理隐患，在加载 P0 特征与 Target 时同步施加：

- **随机大动态平移（Random Shift）**：X/Y 轴各 **±30 ~ ±60 px**，迫使网络学「双翼高亮两端 + 细长对称边缘」的**局部空间拓扑**而非固定坐标。
- **随机水平翻转（Random Horizontal Flip）**：概率 **50%**，打碎人造物单一朝向特征。

### 4.3 损失函数

$$\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{det}}(Y_{\text{GT}}, H_{\text{final}}) + \lambda_{\text{silent}} \cdot \mathcal{L}_{\text{silent}}$$

**(1) 检测损失 `L_det`（Modified Focal / CenterNet 式）**

$$\mathcal{L}_{\text{det}} = -\frac{1}{N} \sum_{x,y} \begin{cases}
(1 - H_{\text{final}})^\alpha \log(H_{\text{final}}), & Y(x,y) = 1 \\[4pt]
(1 - Y)^\beta \, (H_{\text{final}})^\alpha \log(1 - H_{\text{final}}), & Y(x,y) < 1
\end{cases}$$

**(2) 静默/透明度正则 `L_silent`**

$$\mathcal{L}_{\text{silent}} = \frac{1}{HW} \sum_{x,y} \Big( (M_{\text{gate}}(x,y))^2 + (\Delta_{\text{pos}}(x,y))^2 \Big), \qquad \lambda_{\text{silent}} = 0.05 \sim 0.1$$

- **核心物理作用**：**无路灯 / 无大目标梯度强力驱动时，门控必须保持在 0 附近**，
  绝不在没把握的背景上乱放抑制或虚假补偿 —— 保护弱小目标底板。

## 五、验证集构建与三大物理探针

### 5.1 🔴 自顶向下隔离（序列级物理封存）

- **绝对禁止**从已挖好的训练切片库里抽 20% 当 Val —— 会造成前后帧瞬时泄漏，指标虚高到 **99%**。
- **正确做法**：在手头 24 条业务视频中，**完整封存 1~2 条代表性序列**（约 10%~15% 独立架次/时序段），
  **1 帧都不进训练特征池**；再从这 1~2 条未见视频中挖掘 Mini-Golden Val（**约 1,500 帧**）：

```
              Mini-Golden Val 构成（各约 500 帧）
                            │
   ┌────────────────────────┼────────────────────────┐
   ▼                        ▼                        ▼
【业务硬负样本段】      【业务大目标漏检段】     【锚定防误伤段】
  路灯最亮段                近距大目标段            微弱平飞/天空段
  考核: 路灯彻底消音        考核: 能量中心汇聚        考核: 基础响应零损伤
```

- **一致性**：本做法与本项目既有的「5-Fold 防泄漏划分」 doctrine 一致，属**沿用既有铁律**。
- **验证特征 In-Memory 常驻**：1,500 帧 `(feat_p0, h_base, gt)` 固化为单张量包（约 1.8 GB），单 Epoch 验证 **< 2 秒**。

### 5.2 三大物理探针与一票否决

| 探针 | 计算式 | 交付达标红线 | 物理意义 |
| :--- | :--- | :--- | :--- |
| **$P_{\text{suppress}}$** 路灯压制率 | $\max_{(x,y)\in\text{Lamp}} H_{\text{final}}(x,y)$ | **< 0.10**（原生约 0.55） | 路灯是否彻底消音、不触发单帧报数 |
| **$R_{\text{large}}$** 大目标召回率 | $\sum \mathbb{I}\big(\max_{\text{bbox}} H_{\text{final}} \ge 0.25\big) / N_{\text{large\_gt}}$ | **≥ 90.0%** | 近距大尺寸机身能否稳定聚合并召回 |
| **$S_{\text{anchor}}$** 天空锚点保真度 | $\text{mean}\big(H_{\text{final}}/H_{\text{base}}\big)_{\text{target\_peaks}}$ | **≥ 0.95** | 弱小天空目标响应未被门控误杀 |

- **最佳权重挑选 / 早停**：每 Epoch 跑三探针，一旦**同时**满足
  `P_suppress < 0.10 且 R_large ≥ 90% 且 S_anchor ≥ 0.95` ⇒ **立刻早停并保存为交付权重**（预期 **5~8 Epoch**）。

## 七、🔴 实施前必须先解决的冲突与缺口（本节为本档最高价值部分）

> 以下 7 条**不是**对方案的否定，而是本项目既有铁律/已归档教训与该提案的**真实冲突点**。
> 逐条要么取得用户显式豁免，要么改设计，**不得默认忽略**。

### 7.1 🔴 直接违反**铁律二**（缓存体积红线）——需用户显式豁免

- **铁律二原文**：pkl 等 Cache 必须极度精简，**严格控制在 100 MB 左右，严禁数十 GB 级冗余缓存**；
  严禁缓存全图热图 / 原始图像 / 高维稠密特征图；全量 31,613 帧必须压到 15~50 MB。
- **本方案**：3,000 帧 **≈ 3.9 GiB** + Val **≈ 1.8 GB**，且缓存的是 **FP16 高维稠密特征张量**（命中铁律二两条禁止项）。
- **规模差异的客观说明**：铁律二的原始动机是「31,613 帧 → 30~50 GB 爆盘」，本方案 3,000 帧 → 3.9 GiB，
  数量级差约 **10×**，磁盘压力可控。**但「可控」不等于「合规」。**
- **处理选项（需用户裁决）**：
  1. **显式豁免**（推荐，仿 `rules.md` 铁律一「单次显式豁免先例」写法），在 `rules.md` 写明豁免范围、容量上限（建议硬上限 **8 GiB**）与有效期；
  2. **改设计**：特征降 int8 / 降分辨率 / 只存融合前必要层；
  3. **不缓存**：3000 帧的底模前向成本本就不高，直接在线前向，避免踩铁律。
- ⚠️ **无论选哪条，缓存前必须先给 GiB 估算**（铁律二义务），且不得写入 1TB 卷以外的盘。

### 7.2 🔴 违反**铁律六**（零初始化恒等门控 + Epoch-0 零回归校验）——设计缺口

- **铁律六原文**：新增特征分支**强制配备零初始化恒等门控（`alpha=0.0`）**，保证第 0 步严格等价于底模，实现 Zero Regression；
  且**必须先完成 Epoch 0 零回归校验**；BN 必须锁 `eval()` 不更新 buffer。
- **本方案缺口**：两条专家支路都带 `BatchNorm` 且**未声明任何零初始化恒等门控**，也未声明 Epoch-0 零回归校验。
  融合公式虽然**在 `Δ_pos ≡ 0 且 M_gate ≡ 0` 时数学恒等**，但**参数初始化未保证这一点**
  （Sigmoid 前若是随机 bias，`Δ_pos` 与 `M_gate` 初始即非 0 ⇒ Epoch 0 不等价底模）。
- **必须补齐**：
  1. 🔴 **不能简单地把末层 1×1 Conv 的 weight/bias 全零初始化** —— 全零 bias 经 Sigmoid 后输出恒为 **0.5**，
     既不是 0 也无法学（梯度被截断）。正确做法是三选一：
     **(a)** 末层 bias 初始化为使 Sigmoid 输出 ≈ 0 的负值（如 `bias = -20` 量级）并**冻结**；
     **(b)** 末层后接可学习标量门控 `α`，**`α = 0.0` 初始化**（铁律六的原始写法，推荐）；
     **(c)** 末层改 `ReLU` 输出再乘 `α`。
     ⇒ 验收标准统一为：**Epoch 0 实测 `Δ_pos ≡ 0` 且 `M_gate ≡ 0`**（不是「初始化得看起来像 0」）。
  2. `Expert_Suppress` 同理，必须保证 Epoch 0 时 `M_gate ≡ 0`；
  3. **两条支路的 BN 全部锁 `eval()` 且 `requires_grad=False`**，只训卷积权重；
  4. **Epoch 0 零回归校验**：`H_final` 与 `H_base` 逐像素 bit 级比对，差异必须为 0，且 Anti-UAV 指标对齐 §一.2 记录的浮点基线。
- **参考已有成功先例**：`WhHead` 实验（`memory.md` §十一.5）已跑通「底模冻结 + 新增侧支 + Epoch 0 对账 `F1=0.906338 / TP=21,642 / FP=1,004 / GT=25,111`」，
  **该脚本的冻结与对账模式可直接复用**，不必新写。

### 7.3 🔴 特征链必须复用现有算子，否则基线不可比

- 现有业务域全量评测链（**F1 73.58% / R 69.06% / P 78.74% / FAR 0.1496**）由
  `manu/data/multiscale_heatmap_cache.py` + `manu/videos/render_multiscale_osd_video.py` 承担，
  memory 已有铁律：**「推理链与评测大盘同一份代码」**。
- **要求**：P0 特征缓存的生成**必须复用既有算子**（同一 GMC / 21 帧中值 / 多尺度融合 / 抽峰实现），
  **严禁另写一套**。否则「有 adapter 的 F1」与「73.58% 基线」不可比，A/B 失去意义。
- ⚠️ 另注：多尺度融合口径为 `scales 160,80 / threshold 0.30 / merge-radius 64 / region-threshold 0.06`，
  **而 §三.1 的挖掘门限用的是单尺度 `0.22`** ⇒ **挖掘源与评测源口径不一致**，
  挖出来的「硬负样本」未必是评测大盘中真实 FP 的来源。
  **必须先用多尺度融合后的热图挖桶，或至少在 Step 0 复核桶内 FP 与大盘 FP 的一致率。**

### 7.4 🔴 坐标系与 `imgsz` 红线（既有铁律，方案未声明）

- 既有铁律：**原生图像坐标与 640×640 Letterbox 坐标严禁混用**；**不得硬编码 `imgsz=640` 做原生坐标采样**。
- 方案 §三.1、§五.2 出现 `15 px`、`Box_Area > 100 px²`、`max_in_bbox H ≥ 0.25`、±30~60 px 平移 ——
  **全部必须声明所属坐标空间**（原生 640×512 vs letterbox 640×640）。
- **要求**：实现时每个距离/面积判据显式带 `coords=` 参数并在日志打印口径；热图密度换算遵循
  既有公式「**1 输入像素 = 8 原生像素**」（memory 已记录 80 尺度量化误差 4.5 px）。
- ⚠️ **已归档同类事故**：float16 存坐标导致 `TP −3 / FP +3` 的口径漂移（见 `memory.md` GMC-Net 段）——
  **特征与坐标缓存一律 float32**。

### 7.5 ⚠️ `S_anchor` 探针在乘性压制下可能被自身机制误判

`S_anchor = mean(H_final / H_base)`：若 `M_gate` 在天空目标处误触发微小值（如 0.02），
即使目标不受影响，比值也会拉低而**误报退化**；反之若分母落在极小值（`H_base ≈ 0.01`）上，比值会被放大。
**实现要求**：比值只在 `H_base ≥ 0.22`（即底模已检出）的峰点上统计，且**同时报告 `M_gate` 在天空 ROI 上的最大值**
作为补充证据，不能只报比值均值。

### 7.6 ⚠️ 方案覆盖面 < 交付判据缺口（7 条 Bad Case 未全覆盖）

- 当前业务域 **F1 73.58% / R 69.06%**，判据 **F1 ≥ 88% 且 R ≥ 85%**，缺口约 **+14.5 F1 点 / +16 R 点**。
- 本方案只覆盖 **路灯虚警** 与 **近距大目标** 两类。而 §5d 定位的 7 条 UN-PASS 中，
  `VIDEO00006_000322`（F1 63.97%，**头号事故 FN 6,847**）与 `VIDEO00036_015740`（F1 24.03%）属**能力缺口**，
  **不在本方案射程内**；`00032_014453` 属**黑热截断**，需 §十.1 的反相路线，**本方案也不覆盖**。
- ⇒ **必须预先承认**：即便本方案完全成功，也不保证达标；不得把「路灯消音 + 大目标召回」直接等同于「F1 ≥ 88%」。
- **建议 Step 0**：先做 **FN 拆解**（既有 `fn_absent` / `fn_compete` 拆分工具）确认这 14.5 个 F1 点到底分布在哪些序列/桶，
  再决定本方案的优先级是否足够。

### 7.7 ⚠️ 硬件口径：`NPU` 阻塞项未因本方案改变

- 方案目标硬件为 RK3588，但 memory 已确证：**`/dev/rknpu` 不存在、`/proc/devices` 无 rknpu、`librknnrt.so` 已装但无设备节点**
  ⇒ **NPU 驱动未使能，RKNN 路线当前走不通**；且 **Trial 0474 无任何 NPU 部署产物**（全仓唯一 onnx 属已止损的 YOLO26s 路线）。
- 本方案为**外挂旁路**，只增加 ~30k 参数的两次卷积前向，**不改变 NPU 阻塞事实**，也不产生 NPU 部署件。
- **收益评估须按 memory 已确立的口径**：加速比**必须同时报点数/纹理水平**，否则不可迁移；
  板卡时延**只认本地盘数据 + `--timing` 分段表**，**PoCL / CPU 模拟时延严禁当作板卡性能**。

## 一、要回答的决定性问题

**`trial_0049` 能否在 T1 上过红线 `0.8958967482400269`，同时保住它最高的 T3（0.906392）？**

### 结论：**不能。**（T1 侧过不了红线 ⇒ "兼得"不成立；T3 侧不受影响，0.906392 原样保住）

把长泉山 T3 管线里那条 **area/sums 判别式候选门**原样移植到 T1 之后，
**T1 的最优 F1 一点都没有被抬起来**：能被门抬起来的配置一个都没有。

**任何真正删掉候选的门都让 T1 F1 下降**（`trial_0049` ct=0.06 上：门 `sums>=0.6` → F1 −0.0111 pp，
`sums>=1.0` → −0.0890 pp，`sums>=1.5` → −0.8701 pp，`area>=5` → −1.1780 pp）。
唯一有正收益的是**上限门**（删"胖"杂波），但幅度只有 **+0.0631 pp**，且要拿 30 个 TP 去换。

**"零 TP 损失下的最大 FP 削减"（决定性指标）**
| 模型 / ct | 零 TP 损失能砍掉的 FP | 过线需要砍掉 |
|:--|--:|--:|
| `trial_0049` / 0.06 | **0 个** | ≥ 263 个（FP ≤ 1039） |
| `trial_0049` / 0.02 | **1 个**（`sums>=q0.5`） | ≥ 269 个 |
| `cs_t0008p2` / 0.06 | **0 个** | — |
| `cs_t0043` / 0.06 | **0 个** | — |

⇒ **T1 的虚警与真目标在 area/sums 上完全不可分**（连"不丢一个 TP"都做不到）。


## 五、**为什么 T3 的门在 T1 上不管用**（结构性原因，不是超参没调好）

1. **算术门槛**：在 th=0.25 的工作点上，要过红线必须满足
   `ΔFP ≥ 263.24 + 1.2448 × ΔTP`（**每丢 1 个 TP 就要多砍 1.245 个 FP**；1.2325 是 `cs_t0008p2` 的比值）。
   实测最好的比值是 `sums>=1.0`：−112 FP / −128 TP ⇒ 比值 **0.875**，**比门槛 1.2448 差 30%**。
2. **T1 的虚警不是"弱虚警"**：th=0.25 处 FP 的分数中位数 0.433、p75 0.579（TP 中位数 0.759），
   活到阈值之上的 FP 本身就是**强杂波**；而 area/sums 下限门只能删**弱**候选
   ⇒ 门和分数阈值抢同一批弱候选，**门永远打不过阈值**。
3. **T1 的 FP 反而更"胖"**：th=0.25 处 FP 的 area 中位数 10、p90 68（TP 中位数 9、p90 20）
   ⇒ T3 那种 `area_min` 下限门在 T1 上方向是**反的**（实测 `area>=5` 直接掉 1.18 pp）。
   补测的 `area<=` / `sums<=` 上限门同样不成立（最优比值 0.56 < 1.23）。
4. **T3 门的真正火力来自"多尺度 tag 维度"**：T3 候选池是 640/160/80 三尺度合并，
   `tag_allow` + `tagq` 能量门删的是"只在粗尺度上冒头、能量又低"的候选。
   **T1 只有单尺度（stride-2 原生格）**，缺了这一维 ⇒ 判别力无处可来。
5. **连通域阈值（`component_thresh`）的关系**：`conf_thresh=0.02` 决定"要不要缓存这个峰值"，
   `component_thresh=0.06` 决定"这个峰值的能量在哪个 blob 上量"。
   取 0.06 时，缓存里 **59%~65% 的候选 score < 0.06 ⇒ area=0/sums=0**（它们被 `area_min>=1` 直接滤掉）；
   取 0.02 时每个候选都有连通域，`area_min>=1` 恒为 no-op。
   **两种取法都测了，结论一致（见第六节）。**

## 六、未验证 / 未做

- `component_thresh` 只测了 `0.06` 与 `0.02` 两个值（`0.22` 未测；`0.22` 会让 `area_min>=1`
  退化成"把阈值抬到 0.22"，属阈值改动，不测）。
- 分位数门（`tagq` 同构）的**总体是评估集内拟合**（与 T3 同病），本轮结论是"负向"，故不构成风险。
- 上限门（`area<=` / `sums<=`）是**超出 T3 配方**的扩展探测（只在 ct=0.02 缓存上有正收益），
  只为把结论证死，不建议作为交付件。
- 没有测「多尺度 T1 候选池」（那才是 T3 火力的真正来源），属于**新推理路径**，本轮未授权。
- 没有改 T3 管线（`system_sota_longquan.py` / `eval_multiscale_cache_th.py` 一个字没碰），
  ⇒ `trial_0049` 的 T3 = 0.906392 **不受本次移植影响**。

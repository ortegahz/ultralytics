# 核心执行铁律与服务器运行环境规范 (Rules & Environment)

> **文档定位**：约束 Agent 与用户协作边界、保障数据资产安全、标准化服务器连接与挂载环境。每次涉及脚本生成、缓存构建、命令交付与文件同步时必须严格遵照执行。

---

## 一、四大核心铁律 (STRICT ENFORCEMENT)

### 1. 【核心铁律一】严禁 Agent 擅自启动任何训练、推理或重型探测脚本！
- **分工边界**：一切代码修改、算法设计、参数调优系统与执行指令由 Assistant（Agent）负责编写完毕；所有训练、推理、缓存提取、评测与微调脚本**必须且只能由用户在目标服务器或本地环境中手动执行**。
- **闭环协作模式**：Assistant 负责准备好清晰、无歧义的完整命令（含环境变量、工作路径与传参说明）交付给用户，由用户运行后将终端指标结果反馈给 Assistant，Assistant 再基于实测事实推进下一阶段分析与算法演进。
- **严禁在后续任何 Session 中再次尝试后台自启或前台偷跑命令**，牢记用户算力资源的绝对控制权！

### 2. 【核心铁律二】pkl 等 Cache 缓存文件必须极度精简，容量严格控制在 100MB 左右，严禁写入数十 GB 级冗余缓存！
- **严禁缓存大尺寸张量**：严禁在缓存 pickle 中保存全图热图（320x320 float32）、原始图像或高维稠密特征图（否则 31,613 帧会膨胀到 30GB~50GB 塞爆硬盘与内存）；
- **极致瘦身规范**：
  - 仅保留提峰后的候选离散稀疏点坐标 `points`（float16）与置信度 `scores`（float16）；
  - 每帧限制存储 `top_k <= 100`；
  - 真值仅存 `gt_pts`（float16）；
  - 全量 31,613 帧的 `.pkl` 文件体积必须严格限制在 **15MB ~ 50MB（至多不超过 100MB）**，确保加载在 1 秒内完成、内存零压力。

### 3. 【核心铁律三】本地代码修改后必须自动无感同步至服务器映射目录！
- **自动同步义务**：本地任何代码、脚本、配置或文档在完成修改/新建后，Assistant 必须**立即主动将其复制同步到服务器 SSHFS 挂载工作目录**（`/home/manu/mnt/pycharm_project_10ae9e2e/`）；
- **杜绝用户二次操作**：用户无需手动复制或同步代码，保证服务器端环境永远处于最新的就绪状态。

### 4. 【核心铁律四】实验事实与阶段性结论必须自动实时更新到 memory 体系，严禁等待用户催促！
- **主动建档义务**：任何代码级、模型级、输入级或后处理级的实验尝试（无论最终是指标突破还是遭遇衰退被证伪），只要产生了大盘实测数据或关键物理定性，Assistant **必须自动、主动将其作为独立记录沉淀归档到 `memory/` 相应模块与主索引 `memory.md`**；
- **全周期自闭环**：包含实验动机、设计方案、完整大盘指标对比表格、物理成因深度定性与最终工程决策，免去用户重复提醒，保证后续任何新会话（New Session）能无缝继承完整的技术上下文。

### 3. 数据集坐标对齐铁律 (Zero Coordinate Drift)
- 官方数据集（如 `/mnt/data/siping/datasets/manu/uav` 及镜像集 `uav_gmc_median`）是经过严格规范预裁切与坐标归一化的，`labels/val/*.txt` 与图像呈现绝对严格对齐；
- **严禁脱离官方标准验证集自立评估流**：直接拿 raw 序列做自适应 letterbox 缩放会引入像素级 padding 漂移，造成假性严重漏检与误报；任何新特征生成必须采用 1:1 就地镜像转换。

## 一、请外部模型先理解的核心结论

### 1. 项目研究对象

项目面向低空安全场景中的复杂背景红外弱小无人机检测，目标尺寸通常为 **1~3 像素**，目标在红外焦平面上更接近光学点扩散函数（PSF）或弱冲激，而不是具有清晰纹理和部件结构的普通视觉目标。

这决定了项目不能简单套用常规大目标检测结论：

- Bbox 回归容易发生小框塌缩；
- 单纯增大骨干容量不能凭空创造目标能量；
- 目标峰值可能低于单帧全图噪声极值；
- 运动和时间上下文比单帧语义更重要；
- 标注中心误差、坐标空间错误、输入通道顺序错误都可能直接改变实验结论。

### 2. 当前最重要的两个基线

必须严格区分单帧模型指标和系统级后处理指标：

#### 单帧模型绝对基线：Trial 0474

- 权重：`runs/optuna_p0_nas/trial_0474/weights/best.pt`
- 架构：YOLO26 Heatmap Detector；P0-NAS 微架构为：
  - `standard_dw`
  - `pixel_unshuffle`
  - `diff_only`
  - `depth=2`
  - `scalar_gate`
- 输入契约：
  ```text
  [I_t, |I_t - W(I_{t-2})|, (I_t - B_t)^+]
  ```
- `W`：在原始灰度帧上估计 GMC 后的历史帧对齐结果；
- `B_t`：GMC 对齐后的 21 帧滑动时域中值背景；
- 统一验证集：24 个序列、31,613 帧、25,111 个 GT；
- 匹配标准：Distance <= 8.0 px；
- 评测结果：
  - Recall：86.19%；
  - Precision：95.57%；
  - F1：0.9064；
  - TP：21,643；
  - FP：1,004；
  - FAR：0.0318 个/帧；
  - 最佳阈值：0.25。

Trial 0474 是当前永久冻结的单帧模型基线。后续任何单帧输入、结构、损失或侧支实验都必须首先与它做 Ep0 零回归对账。

#### 系统级交付基线：Trial 0474 + 双向时空后处理

完整系统包括：

1. Trial 0474 单帧候选点；

## 二、数据、输入和评测契约

### 1. Anti-UAV 官方开发数据

统一大盘：

```text
验证序列：24
验证帧数：31,613
GT 总数：25,111
匹配标准：Distance <= 8.0 px
```

训练集和验证集工程数量：

```text
训练样本：43,008
验证样本：31,613
```

数据中存在混合原生分辨率：

- `640×512`
- `512×512`

因此必须区分两个坐标空间：

1. **原生图像坐标**：用于从原始图像采样灰度、差分、中值通道；
2. **640×640 Letterbox 坐标**：用于 Ultralytics 推理缓存和系统级评测。

严禁把归一化坐标统一乘 640 作为原生 y 坐标，否则在 `640×512` 图像上会产生约 50 像素的系统偏移。

### 2. GMC 与时域中值输入生成

正确流程：

1. 在原始灰度图 `I_t`、`I_{t-1}`、`I_{t-2}` 上估计 GMC；
2. 使用稀疏 LK 光流 + RANSAC 估计仿射运动；
3. 将历史原图 warp 到当前帧坐标；
4. 计算短时差分：
   ```text
   Diff = |I_t - W(I_{t-2})|
   ```
5. 在 21 帧对齐历史原图上计算中值背景：
   ```text
   B_t = median(W(I_{t-i}))
   ```
6. 计算正残差：
   ```text
   MedianResidual = (I_t - B_t)^+
   ```

Trial 0474 的永久输入语义是：

```text
[I_t, |I_t - W(I_{t-2})|, (I_t - B_t)^+]
```

注意工程实现中的 BGR/RGB和通道写入顺序：官方三通道 Format 会做 BGR→RGB翻转，多于三通道时不会自动翻转。扩展通道时，已有前三通道必须直接读取官方数据集图像，不能从 raw 重新生成，否则 JPG 有损像素差异会造成基线漂移。

### 3. 评测口径

每个实验至少报告：

- Recall；
- Precision；
- F1；
- TP；
- FP；
- FN；
- FAR；
- 最佳阈值；
- 评测匹配规则；
- 是否为单帧还是系统级；
- 是否使用 In-BBox 还是 Strict Distance；
- 是否使用独立测试集或开发验证集。

仅报告 F1 不足以判断算法是否真正进步。尤其需要警惕 Recall 上升但 Precision 明显下降造成的虚假 F1 改善。

## 三、算法演进全景

### 1. 数据和基线阶段

1. 公司数据初步摸底，发现数据多样性、极小目标覆盖和复杂背景不足；
2. 引入公开 Anti-UAV 红外数据作为算法开发基座；
3. 建立防数据泄漏的数据划分和全量统一评测大盘；
4. 以 YOLO26 Bbox 检测器建立常规基线；
5. 发现 1~3 像素目标不适合传统 Bbox 回归；
6. 引入 P2/P1 高分辨率 Heatmap 点回归范式。

早期代表性结果：

| 方案 | 范式 | F1 | 结论 |
|---|---|---:|---|
| YOLO26 Bbox `trial_0028` | P2 Bbox | 0.7631 | 小框塌缩，作为传统基线 |
| Heatmap 早期模型 | Anchor-free 点回归 | 约 0.8331 | 明显优于 Bbox 范式 |
| Trial 0031 | Heatmap P1 | 约 0.8898 | 高分辨率点检测有效 |

### 2. 输入管道阶段

主要进展：

1. 原始短帧差输入；
2. GMC 全局运动补偿；
3. 21 帧时域中值背景建模；
4. Focal Loss 负样本软化；
5. 形成 Trial 22；
6. P0-NAS 产出 Trial 0474。

关键物理认识：

- GMC 必须在原始灰度图上估计，不能在差分图上估计；
- GMC 消除相机抖动造成的结构性白边；
- 21 帧中值背景可以压制随机背景噪声；
- 时域中值对移动目标有效，但对长时间悬停目标可能产生自吞噬；
- `(I_t-B_t)^+` 对黑热暗目标存在结构性不利。

### 3. 时序和结构探索阶段

曾尝试：

- 原始 3-Frame 图像堆叠；
- 帧差多通道输入；
- 辅助位移矢量多任务学习；
- Hybrid Corr 局部相关层；
- Tubelet 时序注意力；
- 浅层多尺度时序卷积 NAS；
- 点流 DP-TBD；
- 匹配滤波独立检测器；
- 速度滤波组；
- 多尺度和 TTA；
- YOLO26s 骨干扩容；
- 亚像素能量守恒损失；
- 形态学、暗残差和速度残差侧支。

总体结论：简单增加时序通道、在固定空间网格做时序卷积、无门控地累加低分候选、或直接微调已收敛模型，都不能稳定突破 Trial 0474。

### 4. 时空后处理阶段

后处理从简单在线关联逐步发展为：

- 高分候选发起航迹；
- 弱候选只能被已有航迹打捞；
- 空域悬停豁免；
- 速度相关关联门限；
- 双向平滑；
- 轨迹碎片缝合；
- 高置信航迹短缺口插补；
- 刚性静止坏点剪枝。

最重要的系统突破不是新模型，而是发现并剪除大量长期固定的坏点型虚警，同时利用时间连续性恢复短暂漏检。

### 3. 刚性坏点剪枝的意义

深度切片诊断发现约 250 处虚警属于长期存活、终生位移小于 2 像素的固定坏点或地表微震。

剪枝规则：

- 航迹累计命中至少 8 帧；
- 全生命周期净位移小于 2.0 px；
- 坐标方差小于 0.50 px²；
- 满足条件才整条轨迹删除。

结果：

- TP 22,616 零损失保全；
- FP 减少 117；
- Strict F1 从 0.9172 提升至 0.9194；
- In-BBox 口径达到 0.9209。

工程解释：不是单纯“提高阈值”，而是利用虚警的生命周期物理特征进行剔除。

## 五、主要失败实验和必须保留的技术边界

### 1. 原始 3-Frame 堆叠

将 `[I_t, I_{t-4}, I_{t-12}]` 直接堆叠，依靠网络自己学习时序关系。

失败原因：弱目标在不同时间帧中的位置变化和闪烁被隐式 AND 约束，网络倾向于要求多帧同时出现，反而绞杀短暂弱目标。

### 2. Hybrid Corr

在差分和历史帧之间引入局部相关层，窗口半径约为 2。

失败原因：相关窗口过小，无法覆盖中高速目标的真实位移，导致中高速目标能量无法聚合。

### 3. Tubelet 时序注意力

在固定空间网格上对多帧差分做时序卷积和注意力。

结果：F1约0.8954，门控收敛为微负。

失败原因：目标在时间窗口内发生空间位移，固定位置的时序堆叠不是同一目标的能量；差分下采样又进一步稀释 1~2 像素信号。

### 4. 浅层多尺度时序 NAS

完成 58 组分布式搜索，Top-15 F1 全部落在 0.9063~0.9064。

结论：在已经使用 GMC + 21 帧中值的输入上，浅层局部时序卷积难以获得新的信息增益，继续无差别搜索没有价值。

### 5. 点流 DP-TBD

在低阈值候选点流上加入速度、加速度、转角约束和双向 Viterbi 累加。

结果：

- 激进配置 Recall可达约91%，但 FP 暴增；
- 首轮 F1降至约0.8746；
- 48组搜索最佳 F1约0.9057，仍低于系统基线。

失败原因：低阈值候选池中的白噪声、固定结构和杂波也能被动态规划串成“轨迹”。时空累加不是天然只奖励真目标。

### 6. 亚像素积分能量守恒 Focal Loss

动机是让网络关注小目标邻域的总能量，而不是单个离散峰值。

结果：

- 单帧 TP增加约33；
- 单帧 F1下降；
- 接入系统后净丢失约223个真实目标；
- 难例 `wg011_03` Recall 从56%跌至11.4%。

失败原因：局部积分约束拉平了高斯峰曲率，使置信度在时间轴上锯齿化，原本可被平滑器连接的轨迹变成碎片。

结论：当前三通道管道下，永久停止对收敛检测头和损失进行无约束微调。

### 7. YOLO26s 骨干扩容

严格 A/B：同输入、同数据、同超参、同5轮冷启动。

结果：

- YOLO26n P2峰值F1约0.8188；
- YOLO26s P2峰值F1约0.8228；
- YOLO26s Precision提高、FP减少，但 Recall基本不变；
- P1热启动版本峰值F1约0.8285，Precision 92.03%，但最佳阈值被锁定在0.45，弱目标被截断。

结论：容量扩展主要改善复杂背景抑制，而非弱目标召回；纯骨干扩容路线终止。

### 8. P0/形态学/暗残差侧支

所有侧支必须遵守：

- 底模100%冻结；
- 新分支零初始化门控；
- Ep0浮点级零回归；
- 官方DataLoader；
- 只允许短周期受控验证。

已经验证但未形成净增益的方向包括：

- 动态形态学侧支；
- 暗残差 signed residual 侧支；
- 速度残差旁路；
- 其他浅层时序局部卷积。

共同原因是极端负样本比例下，新增支路容易变成去噪滤波器或负向门控，而不是有效的弱目标增强器。

## 六、Oracle 上界、难例和“人眼能看但模型不行”的解释

### 1. Oracle 上界

在固定 Trial 0474 候选池上，Oracle 分析得到：

- 当前系统 Strict F1：0.9194；
- 固定候选池工程诚实上界 Oracle-B：F1约0.9570；
- Oracle-A纯数学上界：F1约0.9647；
- 剩余 FN分裂为：
  - 前端完全没有候选的死区：1,714，约70%；
  - 候选池中已有弱候选但后处理没有捞到：743，约30%。

因此：

- 后处理调参不能解决 1,714 个前端死区；
- Phase-A 后处理路线已经收益饱和；
- 下一阶段若追求实质提升，应改造输入管道或检测范式，而不是继续调后处理门限。

### 2. Hard Case 1：`wg2022_ir_020_split_03`

基本信息：

- 500 GT；
- 当前 Recall约7.6%；
- Precision约59.4%；
- 总积分能量 `medEnergy=40`，全盘最低；
- 目标大约为2×2像素，仅比背景高约9灰度级；
- 单帧 DoG+CFAR约3.3σ；
- 同帧噪声最大起伏约5.40σ；
- 前端候选覆盖率仅26.4%。

已排除：

- 坐标采样错误已经修复；
- 不是时序通道完全坍塌；
- 不是简单的“云层劫持”；
- 不是目标完全没有物理能量。

正确结论：

> 目标的时间能量是相干的，但单帧检测器无法稳定在目标位置产生高置信候选。瓶颈是“先检测后跟踪”架构的单帧起轨要求，而不是传感器物理上不可探测。

Oracle亚像素积分结果：

| 积分帧数 | SNR |
|---:|---:|
| 1 | 3.89 |
| 3 | 6.74 |
| 5 | 8.72 |
| 9 | 11.78 |
| 15 | 15.35 |
| 21 | 18.54 |
| 75 | 39.14 |

增益严格接近 `sqrt(N)`。

但匹配滤波独立检测器、阈值串联TBD、检测器级分数融合均已证伪：

- 独立匹配滤波器在可接受虚警率下 PD不足；
- 先阈值再TBD有选择偏差，假轨迹也能时间相干；
- 神经网络分数与TBD分数没有可靠统一量纲；
- 持久背景和坏点可以形成强假轨迹。

### 3. Hard Case 2：`DJI_0051_2`

- 目标暗、小，背景像复杂建筑；
- Recall低，FP也高；
- 目视感觉像“雾蒙蒙玻璃上的小黑点”；
- 旧的“多深度视差”解释缺乏充分实测依据，应降级为未证实猜想；
- 当前更可信方向是“暗小目标 + 复杂杂波 + 正残差通道结构性不利”。

当前输入的第三通道为：

```text
(I_t - B_t)^+
```

暗目标满足 `I_t-B_t<0` 时，该通道接近零。暗目标不是单独致命因素，因为其他高能量暗目标序列仍有99%~100% Recall；真正危险组合是“暗 + 小 + 高杂波”。

### 4. Hard Case 3：`wg2022_ir_011_split_03`

- 目标位于云层内，对比度低；
- 只有飞出云层并快速运动时才明显可检出；
- 总能量约108，全盘第二低；
- Recall约56%；
- 与 Hard Case 1 同属低总能量、云层内低对比小目标问题。

### 5. Hard Case 4：`DJI_0175_2`

- 目标在姿态翻滚时出现周期性暗化；
- Recall约61%；
- 但背景极其干净，FP仅约5~6，Precision约98%；
- 已有高质量画中画诊断视频；
- 当前定位为“演示达标/低优先级储备”，不作为三天汇报中主攻的失败案例。

### 6. Hard Case 5：`02_6321_0274-2773`

包含两个完全不同的失效区间：

#### 远距悬停段

- 目标约8~16像素；
- 悬停时间较长；
- GMC短差分和21帧中值均可能把目标吸收到背景；
- Heatmap有约77.3%的漏检样本处于极低响应；
- Bbox对10像素目标也会发生小框塌缩。

#### 近距大机身与建筑边缘重叠段

- 目标可达约99×64像素甚至更大；
- Heatmap的点冲激先验失配；
- 建筑强边缘使热图能量分裂和中心偏移；
- YOLO26 Bbox在该段通常优于 Heatmap。

候选策略：

- 悬停：基于已确认航迹做时间上下文保护，不能只用速度门限；
- 大目标：尺度门控双专家或尺度旁路；
- 当前尚未形成经过全盘定量验证的生产方案。

### 7. 飞鸟和标注质量问题

两大高频虚警序列中共约389处虚警经原片核验属于真实飞鸟。对于1~2像素点目标，滑翔飞鸟与无人机可能物理同构，仅凭单光电红外图像无法可靠区分。

另有序列存在人工标注中心偏移，导致算法命中物理目标但距离中心超过8像素。在10像素工程容差下表现明显改善。

汇报时应把这些内容表述为：

> 评测大盘中的所有 FP 不等于算法错误，其中包括物理不可区分的飞鸟和标注中心偏移；必须区分算法虚警、自然干扰、标注误差和评测口径误差。

## 七、时域积分和速度滤波组的最新结论

### 1. 为什么人眼能看见

单帧目标约3.3σ，而640×512全图噪声最大起伏约5.40σ，单帧统计上难以区分。

人眼并不是单帧比模型更强，而是在连续观察中利用了：

- 运动轨迹；
- 目标出现和消失的时间上下文；
- 相对背景的连续位移；
- 多帧能量积累。

### 2. 速度滤波组实验

在 Hard Case 1 上，采用原始灰度 DoG+CFAR、GMC对齐、固定速度组累加，得到：

| 窗口 W | PD，FAR约0.045/帧 |
|---:|---:|
| W=1 | 0.8% |
| W=3 | 10.6% |
| W=5 | 19.2% |
| W=9 | 16.3% |

W=5是当前固定匀速模型的最佳工作窗，但这是经典候选检测 ROC，不是训练后神经网络 Recall 承诺。

如果后续继续，最小验证方式是：

1. 先用 `frame_stride=1` 复核 W=3/W=5；
2. 若结果稳定，再做一次 Twin A/B：
   - A：原3通道；
   - B：原3通道 + W=5速度滤波特征；
3. 观察 HC1 Recall、全盘 F1、FP/frame和 Anti-UAV零回归。

不推荐展开大规模速度NAS或长窗组合搜索。

### 3. 悬停与坏点的同构性

静态坏点和悬停目标都可以在同一位置积累能量，因此单纯的速度/位移门限会误伤悬停目标。

正确判别信息是：

- 目标何时出现；
- 是否在出现前有运动；
- 是否在之后离开；
- 是否从一开始就在固定位置持续存在。

## 八、龙泉山业务域迁移现状

### 1. 业务素材

交付素材是 H.264 红外视频，源容器约1920×1080，原始 sensor 空间约640×512。视频经过2倍放大、插值和有损编码，无法恢复原始像素，但正确工程流程是：

1. 去除左右黑边约320像素；
2. 去除上下黑边约28像素；
3. 得到有效1280×1024区域；
4. 使用 `INTER_AREA` 缩回640×512；
5. 以原始H.264作为最终数据源，不删除原始视频。

### 2. 业务域主要失效模式

#### 黑热模式

现象：目标相对背景为暗目标，Trial 0474对白热正残差更适配。

正确处理：

```text
I'_t = 255 - I_t
```

然后从反相后的完整灰度帧序列重新计算：

```text
GMC
21帧时域中值
[I'_t, |I'_t-W(I'_{t-2})|, (I'_t-B'_t)^+]
```

不能只反转已有单个通道、已有Heatmap或输出结果，也不能把黑热原图直接送进白热特征管道。

当前只有视频定性观感，尚无完整人工GT支持的 Recall/Precision/FAR，不能写成已证实定量收益。

#### 悬停目标

超过21帧后可能被中值背景吸收。候选处理是对已经确认的航迹保护，并在预测位置局部冻结背景更新，但必须防止固定坏点被锁定。

#### 近距离大目标

Heatmap可能出现：

- 能量摊平；
- 多峰分裂；
- 建筑边缘抑制；
- 中心峰值低于阈值。

已经获得一个定性正向候选：将完整三通道特征图直接缩小到160像素目标尺度，再嵌入640×640输入画布。

通道感知Padding：

- Ch0 灰度使用边缘灰度均值或114；
- Ch1 GMC差分填0；
- Ch2 中值残差填0。

在 `VIDEO00005_19700101_002959` 中观察到近距目标检出明显改善，但目前无GT定量结果，只能表述为“候选旁路”。

#### 云台大动态

快速旋转、回中、变焦和视差可能使GMC失败。候选防御：监控GMC配准残差MSE、Inlier Ratio等健康度，异常时静音差分和中值通道，降级到灰度分支。

#### NUC温漂和固定条纹

候选防御：轻量列固定图案噪声去除、适度CLAHE，但必须经过原始Anti-UAV回归验证。

#### 复杂热杂波

候选防御：用轨迹净位移/总路程比

```text
R = net_displacement / total_path
```

结合 `min_rigid_disp` 和空间方差约束剪枝，但要防止误伤盘旋、变向和短航迹目标。

## 十二、实验和工程铁律

1. 训练、推理、缓存提取、评测和重型探测脚本必须由用户手动执行，助手不擅自启动；
2. 新缓存只保存稀疏点和分数，单个全盘pkl尽量控制在约15~50MB，绝不写入全图热图；
3. 修改代码后同步到服务器代码映射目录；
4. 实验事实、指标和关键物理结论需要同步沉淀到memory体系；
5. 重大非继承性改动必须执行同源Twin A/B冷启动受控协议；
6. 新侧支必须底模100%冻结、零初始化恒等门控、Ep0零回归；
7. 必须使用官方DataLoader，训练43,008样本、验证31,613样本；
8. 混合分辨率数据中严禁混用原生坐标和640×640 Letterbox坐标；
9. 修改现有多通道数据时，前三通道必须读取官方数据集图像，不能从raw重新生成；
10. 所有业务域方案都必须与原Trial 0474做同一连续帧集合A/B，并通过Anti-UAV不可退化闸门。

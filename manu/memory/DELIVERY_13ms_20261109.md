## 3. ★ 必做：板卡侧解码口径

今天定位并修复了 T1 评估链的一个**口径缺陷**：`late_upsample` 的 320 输出是原生 80×80 网格的**最近邻复制**，
而 3×3 max-pool 抽峰的相等判定（`hmax == heatmap`）会把整块 L×L 复制像素全当峰 ⇒
**一个目标裂成 L² 个等分假阳**（实测 FP 317,074 → 1,398）。

- 修复：**在原生网格上抽峰、用 stride×L 解码**（`native_scale=4`）
- **纯解码改动 ⇒ NPU 前向图不变 ⇒ 19.306 ms 不受影响**
- host(torch) ↔ NPU(numpy) 在 `native_scale=4` 下 **8/8 帧逐位一致**（`dxy_max=0`）

**板卡动作（板卡断电期间未做，必须补）**：

```bash
# 1) 重建板卡二进制（新增 --native-scale / --offset-scale / --offset-bias）
bash manu/pipeline/npu/packaging/build_demo.sh          # 产物需带上新参数
# 2) 运行/部署时对本臂必须显式指定原生网格倍数
rknn_heatmap_smoke <model.rknn> <feature.jpg> --th 0.25 --stride 2 --native-scale 4
# e2e_demo / e2e_core 同理：--native-scale 4
# 3) host 侧 host↔NPU 一致性复核
python manu/pipeline/npu/hm_compare_npu_cpu.py ... --native-scale 4
```

> 不加 `--native-scale 4` 时板卡会复现旧 bug（每目标 16 个假阳）——**这是今天唯一的部署硬要求**。

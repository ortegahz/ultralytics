# 异步双频检跟分离系统（Async Dual-Rate Detection-Guided Tracking）

把「高算力、高延迟的全局检测」移出伺服控制关键路径，由轻量局部跟踪器每帧低延迟输出，
检测器只作为后台低频真理校正源。本目录是该系统的 **Python 参考实现（ref）** 与
**三臂对照验收** 的载体。

> **一句话结论**：在龙泉山 001324 序列上，**臂 3 退回重推演 47.79%** 与 **消融 alpha 残差平滑 48.01%**
> **都显著优于纯检测基准 44.64%**——**全 GT 帧**口径臂 3 净差 **+3.15 pp**（z=−6.73，p=1.83e-11）、
> **共同输出帧** **+5.01 pp**（z=−9.02，p=1.73e-19），**两个口径都显著**；
> 本轮修复前这里是「全序列打平」，现在**检跟分离在全序列 headline 上首次真正赢过纯检测**。
> 但 **臂 3 vs alpha 在全 GT 帧上并不显著**（−0.22 pp，p=0.4165），只在共同输出帧上显著
> （−0.57 pp，p=0.0429）——**不能写成「alpha 全面优于臂 3」**。
> **臂 2（纯前向、永不重引导）按定义就是全灭**（**0.38%**，**只活了 431 帧** / 输出覆盖率 **4.1%**）。
> 本轮还修掉了一个**真 bug**（硬拉回时把**合法的 0 速度**换成检测流脏速度 ⇒ Gate 3b 恒 FAIL，
> 现已 PASS、实测误差 0.0 px），并把**速度源**改成可切换三档、默认 `"none"`（不投影，
> = 规格 §三 伪代码语义）——详见 §6.5。

> ⚠️ **方法学提醒（必读）**：
> **Wilson CI 的独立性假设在连续帧上不成立** ⇒ CI 重叠**只能当保守旁证**，**不能当等价性证明**；
> 配对数据必须用 **McNemar 精确二项检验**。本序列上「CI 重叠 + 打平」是
> **锚点密度混淆 + 输出覆盖率差异**共同造成的假象，详见 §6.2。

## 1. 架构

```
   相机 25 Hz
      |  I_t
      v
+---------------------------------------------------------------+
|  FrameRingBuffer  (帧环形缓存，臂 3 需要回看 Δ 帧)          |
+---------------------------------------------------------------+
      |                                          ^
      v                                          |
+--------------------------------+               |
|  快核 LocalPatchTracker         |               |
|  (< 1 ms, 纯 NumPy)             |               |
+--------------------------------+               |
      |                                          |
      v                                          |
+--------------------------------+               |
|  融合 / 退回重推演              |               |
|  (tracker.py, fusion_mode)      |               |
+--------------------------------+               |
      |                                          |
      v                                          |
   输出坐标 (伺服)                                |
      ^                                          |
      |                                          |
+---------------------------------------------------------------+
|  后台慢流 (det_hz=12.5 Hz, Δ=8 帧 ≈ 320 ms 滞后)            |
|  ReplayDetector -> RC2 检测框，携带源帧号 = t-Δ                |
+---------------------------------------------------------------+
```

关键点：**检测框携带「自己是从哪一帧算出来的」源帧号**。臂 3 用它作为第 `t−Δ` 帧的
绝对锚点，从帧环形缓冲里逐帧重推到当前帧，覆盖前向状态。

## 3. 三臂定义（**已拍板，勿改口径**）

| 臂 | 机制 | 代码位置 |
|:--|:--|:--|
| **臂 1 纯检测基准** | 不跟踪。第 t 帧直接甩第 t−Δ 帧算出来的旧检测框（det_hz=25、Δ=8 ⇒ 每帧都有输出，静态硬吃 320 ms） | `arms.py::arm1_detector_only` |
| **臂 2 检跟纯前向外推** | 快核每帧前推；迟到检测**只对比、不回溯、不修正**；`detection_reinit=False` ⇒ 检测流**永远不能**把位置搬回旧检测点 | `arms.py::arm2_forward_only` |
| **臂 3 异步退回重推演** | 迟到检测作第 t−Δ 帧的**绝对锚点**，从帧环形缓存逐帧重推 Δ−1 步到第 t−1 帧，由主流程走完第 t 帧，覆盖当前状态并回写历史；**不加任何人为平滑衰减** | `arms.py::arm3_rollback_replay` + `replay.py` |

**公平性对照臂（不是三拍板臂之一）**：

| 对照臂 | 机制 | 代码位置 |
|:--|:--|:--|
| **（对照）臂 1 同锚点密度（det_hz=12.5）** | 机制与臂 1 **完全相同**（纯检测、不跟踪、甩第 t−Δ 帧的旧框），**唯一差别是 `det_hz` 从 25 降到 12.5**（锚点密度对齐到臂 2 / 臂 3） | `arms.py::arm1_detector_only_sparse` |

> 它的唯一职责是**隔离「锚点密度」这个混淆变量**（臂 1 是每帧一个锚点，臂 2/臂 3 是每 2 帧一个），
> 详见 §6.3.3。

机制开关：`TrackerConfig.fusion_mode ∈ {"alpha", "replay", "none"}`；
**速度源开关**：`TrackerConfig.velocity_source ∈ {"none", "history", "detection"}`，
**默认 `"none"`（不投影）**——三档语义与实测依据见 §6.5。

### 评测口径（**时序对齐**，非单帧 mAP/F1）

对物理时刻 t：快跟踪器拿到 `I_t` 后**立刻**输出 `(x̂_t, ŷ_t)`，立即与**第 t 帧的 GT** 对账；
此刻后台喂进来的只能是 `Det_{t−Δ}`。指标口径：

- **CLE** = 中心位置误差，统计 p50 / p95 / p99 / max；
- **HitRate@T** = `CLE_t ≤ T` 的帧占比（T=5 px），附 **Wilson 95% CI**；
- **存活窗口命中率** = 仅在**「有输出 ∧ 目标存在」**的帧上的命中率
  （臂 2 一旦失锁就整段报废，不报这个数就看不出它活着时跟得准不准）；
- **Max Jitter** = `max|Δv_t|`，`Δv = (p_t − p_{t−1}) − (p_{t−1} − p_{t−2})`；
- **端到端延时** p50/p99（ms）；
- **输出覆盖率** = **目标存在（有 GT）的帧**里**有输出**的帧占比。

> ⚠️ **覆盖率口径已修正（本轮）**：旧口径的分子含**无 GT 帧**、分母却只用 GT 帧，
> **系统性高估 2.7~3.4 个百分点**，且**各臂高估量不同** ⇒ 跨臂比较失真
> （`three_arm.py::_arm_diagnostics` 的注释即此口径）。
> **新口径**：分母 = 目标存在的帧，分子 = **这些帧上**有输出的帧。

### 各列的分母（**显式列出，不可混用**）

| 列 | 分母 | 分子 / 口径 |
|:--|:--|:--|
| 命中率 HitRate@5px | 全部**目标存在**的帧（10,535） | `CLE ≤ 5 px` 的帧（某臂无输出 ⇒ 计入分母、不算命中） |
| Wilson 95% CI | 同上（按二项比例算） | — |
| 存活窗口命中率 | **有输出 ∧ 目标存在**的帧 | `CLE ≤ 5 px` 的帧 |

### 6.2 读法（速度源语义修正 + bug 修复后的结论，**方向与旧版相反**）

#### 6.2.1 「臂 1 / 臂 3 / alpha 三条命中率互不可区分」是**错的**（修复后连 headline 都翻了）

旧结论有两处**方法学错误**：

1. **锚点密度混淆**：臂 1 用 `det_hz=25`（每帧一个锚点），臂 2 / 臂 3 用 `det_hz=12.5`
   （每 2 帧一个锚点）⇒ 臂 1 的检测信息量是另外两条臂的 **2 倍**；
2. **推断程序用错**：对**配对**数据用了独立样本的 **Wilson CI 重叠**。
   连续帧上样本高度相关 ⇒ CI 重叠既不能证明等价，也不能拿来下「不可区分」的结论。

**正确做法**：对**同一批 GT 帧**做 **McNemar 精确二项检验**（§6.4 配对检验表）。

- **全 GT 帧**（分母 = 全部 10,535 个目标存在的帧）：**臂 3 与 alpha 都显著优于纯检测基准**，
  **McNemar 精确二项 p<1e-10**：
  - 臂 3 比臂 1（det_hz=25）高 **3.151 pp**（z=−6.73，p=1.83e-11，**显著**）；
  - 臂 3 比**同锚点密度**的对照臂（det_hz=12.5）高 **25.401 pp**（z=−44.04，p<1e-300，**显著**）；
  - alpha 比臂 1（det_hz=25）高 **3.370 pp**（z=−7.15，p=9.19e-13，**显著**）；
  - alpha 比对照臂（det_hz=12.5）高 **25.619 pp**（z=−44.78，p<1e-300，**显著**）。
- **共同输出帧**（两臂都有输出的帧）：优势更大，**全部显著**：
  - 臂 3 比臂 1 高 **5.008 pp**（z=−9.02，p=1.73e-19）；比对照臂高 **5.149 pp**（z=−6.62，p=3.85e-11）；
  - alpha 比臂 1 高 **5.082 pp**（z=−9.56，p=1.01e-21）；比对照臂高 **6.378 pp**（z=−8.69，p=3.13e-18）。
- ⇒ **headline 口径也翻了**：本轮修复后，**臂 3（47.79%）与 alpha（48.01%）在全序列上
  都高于纯检测基准（44.64%）**——旧版「三者打平」是**行为有 bug** 时的产物（§6.5）。
  即使臂 1 的输出覆盖率（**91.0%**）仍高于臂 3（**86.2%**）与 alpha（**89.2%**），
  检跟分离**仍然赢**——差距不是覆盖率补回来的，是**净赚**的。
- ⚠️ **必须如实写的反向一条**：**臂 3 vs alpha 在全 GT 帧上并不显著**
  （净差 −0.218 pp，z=−0.85，**p=0.4165** ⇒ 分辨不出）；只有**共同输出帧**口径才显著
  （−0.573 pp，z=−2.07，p=0.04286）。
  ⇒ **不得写成「alpha 全面优于臂 3」**；只能说「两者在全序列 headline 上基本打平，
  alpha 在有输出的帧上略占优」。
- ⚠️ **方法学提醒**：**Wilson CI 的独立性假设在连续帧上不成立**，
  CI 重叠只能当**保守旁证**，不能当**等价性证明**；反过来 p≥0.05 也**不等于**证明了两臂等价，
  只能说「本样本量下分辨不出」。

#### 6.2.2 全序列 headline 的账：**两笔账**（共同输出帧上的赢 vs 无输出帧上的亏空）

**重推演只在约 45% 的帧上触发**（条件化覆盖：vs 臂 1 **47.0%**、vs alpha **45.0%**），
「退回重推演在成功帧上赢、弃权帧上输」**只覆盖了不到一半的帧**，不构成完整解释。
真实机制仍是**「共同输出帧上赢 + 无输出帧上颗粒无收」两笔账**——
但修复之后**两笔账的净值方向都变了**：对臂 1 由「打平」变成**净赢**，
对 alpha 变成**分辨不出**（帧数取自 §7.1.3 的四桶分解，hits 取自 §6.4 配对检验表）：

| 口径 | 帧数 | 臂 3 hits | 对照臂 hits（臂 1 / alpha） | 差 |
|:--|:--|:--|:--|:--|
| vs 臂 1：两臂都有输出 | 8,547 | 4,991 | 4,563 | **+428**（臂 3 高 5.008 pp，z=−9.02，p=1.73e-19 ⇒ 显著） |
| vs 臂 1：至少一臂无输出 | 1,988 | 44 | 140 | **−96** |
| vs 臂 1：**全序列** | 10,535 | 5,035 | 4,703 | **+332**（臂 3 高 3.151 pp，z=−6.73，p=1.83e-11 ⇒ **显著**） |

⇒ 臂 3 在「两臂都有输出」的帧上**对臂 1 大幅赢**（+428 hits，p=1.73e-19），
在「至少一臂没有输出」的帧上仍然颗粒无收（臂 3 只拿到 44 hits，臂 1 还有 140 hits），
**但这笔亏空已经不足以抵消前面的赢** ⇒ **全序列 headline 上臂 3 净赢 3.15 pp**。
⇒ 对 alpha 则相反：**共同输出帧上小幅输，全序列口径上分辨不出**（p=0.4165）——
**两者在 headline 上基本打平**，不要写成「alpha 全面优于臂 3」。

#### 6.2.3 锚点密度是混淆变量 ⇒ 对照臂的意义

- 臂 1 `det_hz=25`（stride=1，**每帧一个锚点**）vs 臂 2 / 臂 3 `det_hz=12.5`（stride=2，**每 2 帧一个锚点**）
  ⇒ **2:1 的锚点密度差**。任何「臂 3 追平臂 1」的结论都被这个变量污染。
- 对照臂「**（对照）臂 1 同锚点密度（det_hz=12.5）**」（`arms.py::arm1_detector_only_sparse`）：
  机制与臂 1 **完全相同**，**只把 `det_hz` 从 25 降到 12.5**。它**不是**用户拍板的三条臂之一，
  职责单一：**把「锚点密度」这个混淆变量单独隔离出来**，让「退回重推演到底有没有用」
  在**同信息量**下重新对照。
- ⚠️ **它的 headline 22.39% 是覆盖率 artifact**：`det_hz=12.5` ⇒ 每 2 帧才有一个锚点
  ⇒ **只覆盖 45.5% 的帧**（臂 1 覆盖 91.0%）；在全序列口径下，没输出的那一半帧全被记成未命中
  ⇒ **22.39% 衡量的是覆盖率，不是精度**。
- **公平比较要看存活窗口命中率**：对照臂 **49.22%** vs 臂 1 **49.06%**（几乎相同）
  ⇒ 纯检测的**精度**与锚点密度无关；臂 1 的优势**全部**来自「每帧都有旧框」这个覆盖率优势。
  而检跟分离各臂的存活窗口命中率（臂 3 **55.41%** / alpha **53.80%** / 弃权兜底臂 **55.89%**）
  都高于两条纯检测臂 ⇒ **在同等信息量下，检跟分离确实更准**。
- ⇒ **全序列 headline 必须与存活窗口命中率一起读**，只报 headline 一定会把
  「覆盖率差异」误读成「精度等效」。

#### 6.2.4 臂 2：只活了 431 帧

- 臂 2 检跟纯前向外推：命中率 **0.38%**、**只活了 431 帧**（输出覆盖率 **4.1%**）、
  脱靶率 **98.7%**、存活窗口命中率 9.28%。
- 原设计是 **32×32 局部质心/峰值提取的快跟踪器**（单帧 **< 0.5 ms**），纯靠自身前推，
  **没有任何纠偏通道**（`detection_reinit=False` ⇒ 检测流**永远**不能把位置搬回旧检测点）
  ⇒ 一旦漂出 32×32 视野就再也拿不回来。
- ⇒ **「快核纯靠自身只能死咬约 431 帧」** 就是这条臂的答案。
  它量化的是**快核自身**的抗累积漂移能力，**不是**「检跟分离失败」的证据：
  臂 3 保留的正是这条被砍掉的纠偏通道。

#### 6.5.1 修掉的真 bug：**0 是合法速度，不得因速度为 0 换源**

旧实现在硬拉回时用「历史速度 v × Δ」把 Δ 帧前的检测位置投影到当前时刻，
但当历史速度**恰好为 0**（目标静止）时，代码**把它换成检测流速度**——
而检测流速度是**跨目标切换**算出来的脏速度（**−2.857 px/帧**），乘 Δ=2 后产生 **5.71 px 假位移**。
⇒ Gate 3b 的双斑合成场景（两斑静止 ⇒ v ≡ 0）**一直 FAIL**。

**修法**：**0 是合法速度**（目标静止），不再因速度为 0 而换源；检测流速度**只在历史速度取不到**
（缓冲里没有可用帧）时兜底。**Gate 3b 现已 PASS**（硬拉回后位置 = `z_f`，实测误差 **0.0 px**）。

根因比 bug 本身更深一层：**硬拉回触发的前提就是「快跟踪器已锁在杂波上」**，
此刻它的**历史速度正是杂波的速度**——用它投影只会把刚拉回的目标**再甩出去**。
这正是 `"history"` 档实测负收益、而 `"none"` 档（不投影）实测正收益的机制解释：
投影位移 p90 **78.11 px**、max **408.90 px**（ROI 只有 32×32），**65.0%** 的硬拉回直接落在
ROI 半窗（16 px）之外，硬拉回后第 1 帧 inbox 命中率只有 **75.0%**；不投影则是 **84.0%**。

#### 6.5.2 初始化也不投影（`_project_to_now` 跟随 `velocity_source`）

SEARCH 初始化分支（`tracker.py::_project_to_now`）原先**无条件**把「Δ 帧前的检测位置」
按速度外推到当前时刻；现在它同样**跟随 `velocity_source`**：`"none"` 档下**直接落在检测框**
（= §三 伪代码的 `self.curr_pos = det_xy`）。

这一步把 **臂 3 从 44.60% 提到 47.79%**、**消融 alpha 从 45.20% 提到 48.01%**（§6.1 验收表）
——**8 帧前的位置外推 8 帧，误差会被放大**，不投影反而更准。

## 7. 归因：三个天花板（**决定结论的关键**）

> 这三个数与本 harness 的实现无关，只取决于**快核能力**与**目标/检测器本身**。
> 没有它们，就分不清「臂 3 效果不好」是**实现不行**还是**前提不成立**。

| 天花板 | 数值 | 含义 |
|:--|:--|:--|
| **快核单步局部误差**（从真值锚点走 1 步） | p50 = 2.22 / p90 = 9.22 / p95 = 13.89 / p99 = 29.97 px；单步有效率 0.866 | 快核一步就有 2.22 px 误差（龙泉山目标是**成簇亮点**：本体+拖尾 ⇒ 质心被拖尾拽偏）。**纯内核能力看 `single_step_error_px_valid_only`**：p50=2.32 / p90=9.04 / p95=13.46 / p99=29.52 px（n=9,112，只含 valid 样本） |
| **重推 Δ 步的累积误差**（从**完美**锚点出发） | p50 = 3.66 / p90 = 13.77 / p95 = 18.76 / p99 = 45.37 px | 这就是臂 3 的**理论天花板**；实跑还要叠加锚点（检测器）误差。能走完 Δ 步的样本 8,459 帧 |
| **锚点误差**（检测框在它自己那一帧） | p50 = 1.87 / p95 = 29.75 / p99 = 341.28 px | 重推演消**不掉**它——消的是累积漂移，不是锚点偏差 |
| **目标在 Δ=8 帧内的真实位移** | p50 = 3.54 / p90 = 51.05 / p95 = 91.47 / p99 = 179.71 px | 纯检测臂的误差 ≈ 锚点误差 ⊕ 这一项 |
| **单帧位移 > ROI 半窗(16 px) 的帧占比** | 3.83% | 快核 32×32 视野追不上的帧 |

> ⚠️ **三个数的样本集合不同，不可直接相减**：
> `single_step_error_px`（n=10,527）**含 invalid 样本**——invalid 时快核位置不动，
> 此时「误差」其实是目标真实位移而非内核误差 ⇒ **想看纯内核能力请用 `single_step_error_px_valid_only`**（n=9,112）；
> `delta_step_error_px`（n=8,459）**只含走通 Δ 步的样本**。
> 另：锚点误差的样本集 n=9,650、锚点口径的 Δ 帧位移 n=10,447（p50=3.54 / p95=84.69 / p99=171.51 px），
> 与上表「可跟性前提」那套（n=10,527）**也不是同一个集合**。

**结论**（注意这是**理论下界 vs 实测**的对比）：臂 1 的误差 ≈ 锚点误差 + Δ 帧位移，
**实测 p50 = 5.19 px**；臂 3 的误差 ≈ 锚点误差 + 重推累积误差，
**理论下界 p50 = 3.66 px**（完美锚点）、**实测 p50 = 4.35 px**。
⇒ 臂 3 的 CLE p50 比臂 1 **好 16.2%**（4.35 vs 5.19 px），比它自己的理论下界（3.66 px）
只高 **18.9%**（旧版口径下是 29%）⇒ 本轮修复后，本序列上「退回重推演」
**换来了可测的精度优势**（配合 headline 47.79% vs 44.64%，p=1.83e-11）。
⚠️ 但**天花板本身没变**（这三个数只取决于快核能力与目标本身，与本轮改动无关）：
单步局部误差 p50 仍是 2.22 px，**快核精度才是下一段的瓶颈**，不是融合策略。

**可跟性前提**（快核视野 = 32×32）：单帧位移 p50 = 0.50 / p90 = 5.83 / p95 = 12.00 / p99 = 31.49 px；
单帧位移超过 ROI 半窗（16 px）的帧占比 **3.83%**；
Δ 帧位移超过 ROI 全跨（32 px）**否** ⇒ 单帧位移超过 ROI 半窗即追不上，
Δ 帧位移超过 ROI 全跨即「退回重推演」在原理上失效（每步都会脱靶 → 弃权）。

## 8. 规格判据 1（异步校正帧一阶位移 ≤ 2 px）：**在当前参数下不成立**

**判据**：异步**平滑校正帧**上的一阶位移 ‖p_t − p_{t−1}‖ 的 p95 ≤ 2 px
（口径 = 走 `smooth` 分支的那一帧；走 `hard_reinit` / `replay` 的帧是**设计内的大跳变**，单列，见 §6.3）。

| 臂 | smooth 桶 StepJump p95 | smooth 桶帧数 | smooth 桶 > 2 px 帧数 | 判定 |
|:--|:--|:--|:--|:--|
| 臂 2 检跟纯前向外推 | 1.33 px | 46 | 1 | ✅ **满足**（p95 1.33 px ≤ 2 px） |
| （消融）残差平滑融合（alpha） | 5.74 px | 3,153 | 540 | ❌ **不满足**（5.74 px > 2 px，540 帧超限） |
| （消融）臂 3 + 弃权硬拉回兜底 | 14.71 px | 122 | 56 | ❌ **不满足**（14.71 px > 2 px） |
| （消融）纯前向 + 允许重引导 | 6.22 px | 3,026 | 468 | ❌ **不满足**（6.22 px > 2 px） |
| 臂 3 异步退回重推演 | — | 0 | 0 | ⚠️ **不适用**（smooth 桶为空） |

- **臂 3 为什么「不适用」**：臂 3 的校正是 `replay` **整段重定位**（从锚点逐帧重推 Δ−1 步），
  属**设计内的大跳变**（校正帧 StepJump p95 = 8.03 px、max = 115.46 px，
  3,422 个校正帧中 645 帧 > 2 px）⇒ **smooth 桶为空**，
  该判据对它**没有定义**，不能拿「没有超过 2 px 的平滑帧」当成通过。
- **定量换算（为什么 α=0.4 / gating=12 px 结构上就过不了）**：
  残差平滑融合的一次校正位移上界是 **α·e ≤ 0.4 × 12 = 4.8 px**
  （`FusionConfig.alpha = 0.4`、`gating_dist = 12.0`，见 `fusion.py`）
  ⇒ **单是上界就已经 > 2 px**；要满足 ≤ 2 px，残差本身必须 ≤ 5.0 px。
  实测 alpha 的 smooth 桶 p95 = 5.74 px（StepJump 量的是**整帧位移**，
  还含快核自己走的那一步）⇒ **判据不成立**。
- ⇒ **结论：α=0.4 / gating=12 px 的参数下，规格的 2 px 瞬态跳跃判据不成立。**
  **不得写成「通过」**；要么改判据的适用对象（明确排除设计内的大跳变帧），
  要么把 α 压到 ≤ 0.17（≤ 2 px 上界）或把门限收紧到 ‖e‖ ≤ 5 px。

| # | 易丢语义 | 代码位置 | 移植时漏掉的后果 |

- **速度源默认 `"none"`（不投影）**：硬拉回与初始化都**不**把「Δ 帧前的位置」按速度外推到当前帧；

  **历史速度取不到**时兜底（§6.5）；

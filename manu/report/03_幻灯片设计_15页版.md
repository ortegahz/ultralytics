### P05 · 战果 A2｜Tree 锚点级联：把 22 次拟合砍到 6.19 次

**主张**：拟合段的 **22 次全量重拟合里，有 16 次是纯冗余的** —— 它们的值可以用已算出的结果**连乘推导**出来。

**版面**：左侧锚点树示意图（**5 个红点 = 直接拟合**，其余灰点 = 连乘推导）；右侧三张说明卡 + 一行实效条。

**原理 · 锚点树**
- 只在 **5 个锚点**网格上直接拟合，其余 **16 个**利用已缓存的步变换**连乘推导**（最大推导深度 **4**）
- 依据：相邻锚点之间的变换关系可由**已算出的步变换复合**得到 ⇒ 同一锚点链上，**推导值 ≠ 独立拟合值**的地方，正是必须用对照臂量出来的那部分偏差

**实效**
- 拟合次数 **22 → 6.19**，拟合段成本 **−48.1%**；**Warp 次数不变**（Warp 是另一块成本，本手段不触及）

**同算法空对照臂法则（本战果的验收底座）**
- 设立 `anchor_step=2` 的**纯重编码对照臂**：不换算法、只改编码路径，用来区分「精度变化来自算法」还是「来自代码污染」
- 结论：精度微降 **ΔF1 −0.0003** 是 **100% 树估算自身偏差**，**绝无代码污染** ⇒ 这个 ΔF1 以后必须作为该手段的**固有代价**记进账本

**来源**：`gmc_net_pending.md` §九·9.1（拟合计数）、§9.4（空对照臂）、§9.3；`gmc_fit_cache_rk3588.md` §1.2；`memory.md` §十六（空对照臂 / 同图对照臂原话）。
**讲述**：1.5 分钟。**空对照臂那段要讲** —— 它是后面 **战果 B4（P10）「等价性四证」**的方法论前身。

### P06 · 战果 A3｜纯函数按绝对帧号缓存：gFTT 才是真正的大头

### P10 · 战果 B4｜多尺度结果融合稀疏化：99.8% 的像素是白扫的

**主张**：**NPU 出的是 multi-scale 分辨率的热图**，后处理要把三块 tile（native 1:1 / thumb160 1/4 / thumb80 1/8）**反投影回 640×512 原生画布做结果融合** —— 本条砍掉这步融合里 **98.5%** 的无效计算，且**输出逐字节不变**。

**版面**：左侧「像素密度」对比条（本页视觉主锚点）；右侧三张卡（洞察 / 做法 / 等价性）；底部两行限制。

> 🔧 **归属口径（必须放在页上，评审第一个会问）**：本条属 **NPU 侧的 multi-scale 结果融合**（stage-3 反投影 + 8 连通域 + 框提取，绑 `pre_cpus` = A55），**与 GMC 的 warp / median 无关**；代码里的 `gmc_post_ms` 是 GMC 拟合**之后**的指纹/NEON 交织/入队开销，**也不是本条**。依据：`manu/pipeline/npu/mosaic_core.h:2119` `BackProjectFrame(s, s->hm, …)` 的输入是 **NPU 前向出的 heatmap**；`manu/pipeline/npu/mosaic_pipeline.cpp:1899-1902` post_loop 注释原文「the back-projection is CPU work of the same family as the composition, so the two belong together and **away from the GMC**」⇒ **本页是战线 B 的一发，不是 GMC 的战果**。

**左 · 主锚点：像素密度**
- dense 每帧扫 **983,040** 个像素（3 tile × 327,680），真实前景只有 **1,822** 像素/帧（mean；p50 1,798 / p90 3,729 / max 5,574）

**中 · 做法：只改「算哪些像素」，不改语义**
- 融合对象是三块 tile 的热图（native 640×512 / thumb160 160×128 / thumb80 80×64），先**反投影回原生画布**再融合

- 浮点累加顺序不变 ⇒ 同一分量的 double 累加序列逐位相同（这是"输出逐字节不变"的**原因**，不是运气）

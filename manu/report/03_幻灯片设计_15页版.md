### P02 · 开篇立靶：阻碍上板交付的两大核心难题

**主张**：管线在板卡上跑起来之后，被两个问题卡住了；后面 13 页全部围绕这两个问题展开。

**版面**：左右双栏。**左＝冷色（难题一 GMC）／右＝暖色（难题二 NPU）**，沿用参考稿的色相对立。

**左栏 · 难题一：GMC 性能黑洞**（副标：算力账本算不准，吞吐成整条管线瓶颈）

- 饼图：拟合 21.6% + Warp 43.7% + 中值 33.7% ⇒ **合计达 183.32 ms/帧**
- 环形图 78.5%：板卡实测端到端墙钟 **79.95 ms**，GMC 独占 **62.765 ms**
- 稳定性的新硬约束：
  - ✗ **曾被误判**：只看是否丢帧
  - ✓ **真相**：深原始缓冲虽已把丢帧归零，但「零丢帧」变成了**锚定精确等价必须守住的死前提**

**右栏 · 难题二：NPU 效率反直觉**（副标：「编译通过」≠「跑在 NPU 上」≠「算得快」）

- 算子暗礁：部分算子（如 Reshape）悄悄回退 CPU，不抛异常、不改指标（**静默失效**）
- FLOPs 外推彻底失效：删减某分支后，MAC 算力仅降 **6.8%**，但时延暴降 **46.5%**！效率卡在**空间乘积**上限
- 量化死胡同：混合精度下输入 dtype 成硬闸门，**FLOAT16 输入耗时高达 45.41 ms**（真 INT8 仅需 **0.34 ms**）

**来源**：`gmc_net_pending.md` §八·8.3、§九、§十七；`heatmap_npu_trial0474.md` §零；`MOSAIC_RK3588_20261026.md` §2。
**讲述**：2 分钟。这一页决定后面每一页的「打的是哪一条」。

### P04 · 战果 A1｜OpenCL 融合内核：啃下最硬的 77.4%

**主张**：把 step10 砍不动的那一块整体搬到 GPU（Mali-G610），并且是**逐位**搬过去的。

**版面**：左侧终端黑窗（原始日志）+ 精度小表；右侧三张说明卡。

**左**：终端窗（**这是本页最有说服力的元素，别改成文字描述**）

prune round 1 → 109 comparators

|:--|--:|--:|

**右三卡**：
1. **完备证明，拒绝抽样** —— 排序网络经过 **109 次比较器**的数学完备证明（2²¹ 全枚举），彻底证伪公开流传的假算法，抓出 **3 个偶发缺陷**

### P05 · 战果 A2 & A3｜算法瘦身：级联与纯函数缓存

**主张**：GMC 内部有两块重复计算，一块砍「次数」，一块砍「重算」。

**版面**：左右双栏。

**左 · 战果 A2：Tree 锚点级联**（配锚点树示意图：5 个红点＝直接拟合，灰点＝连乘推导）
- **原理**：仅在 **5 个锚点**网格直接拟合，其余 16 个利用已缓存的步变换连乘推导（最大深度 4）
- **实效**：拟合次数 **22 → 6.19**，成本大降 **48.1%**（Warp 次数不变）
- **同算法空对照臂法则**：设立 `anchor_step=2` 的纯重编码对照臂，证明精度微降（ΔF1 −0.0003）是 **100% 树估算自身偏差**，绝无代码污染

**右 · 战果 A3：纯函数按绝对帧号缓存**（配环形图：角点检测 gFTT 65.8%）
- **真相剖析**：
  - ✗ **曾被误判**：光流金字塔是瓶颈
  - ✓ **真相**：金字塔构建仅占 **3.2%**，真正的开销大头是角点检测（占 **65.8%**），它是被反复重算的纯函数！
- **极致复用**：将 Resize、角点、金字塔三项按绝对帧号深度缓存
- **实效**：单次 fit 从 **18.46 ms 骤降至 3.94 ms（4.68×）**；产物 MD5 与基线**逐位相同**

> 🔧 **口径注（本次新增，参考稿没有）**：4.68× 是**单次 fit** 口径，不是端到端收益；且加速比必须附带该序列的纹理水平 —— 15.7 角点 → 4.30×，291.9 角点 → 仅 1.37×。引用 4.68× 而不报角点密度，等于把一个场景的数字当通用结论。

**来源**：`gmc_net_pending.md` §九·9.1 / 9.3 / 9.4 / 9.6；`gmc_fit_cache_rk3588.md` §1.2 / §2.1 / §4 / §5 / §6。
**讲述**：2 分钟（本页信息密度最高）。

### P06 · 战果 A4｜帕累托旋钮：深度 D=3 与 D=64 各司其职

**主张**：算得快不等于跟得上；吞吐与延时的物理互斥，必须通过业务场景选档分发。

**版面**：中央「旋钮」隐喻 + 下方四行对照表（每行一个指标，左右两档）。

| | **实战闭环档（D=3）** | **吞吐交付档（D=64）** |
|:--|:--|:--|
| **FPS 吞吐** | 12.880 | ✅ **14.037**（唯一过硬考核 14+ 档） |
| **延时 p95（代价）** | **481.0 ms**（亚秒级响应） | ⚠️ **8058.8 ms**（延时 ×16 倍） |
| **每 Worker 内存** | **7.3 MB**（无总线压力） | 157.3 MB |
| **场景定论** | ✅ 伺服转台 PID 在线跟瞄**唯一可用** | ✅ 离线录像回放、纯吞吐检索**最优** |

**差账行**（本次新增）：D=64 换来 **+1.16 fps / +650 交付帧 / −727 丢帧**，代价是 p95 延时 **×16.75**、每 Worker 内存 **×21.4**；两档精度**都无损**（稳态逐位相同 7045/7045 与 7030/7030，F1 均 = ref），管线健康度计数全 0。

**结论行**：D=3 是低延时实战场景的帕累托最优解，但**不是全局唯一答案** —— 伺服转台闭环超过 1 秒延时会 PID 相位滞后直接脱靶 ⇒ D=64 的 p95 8.06 s 不可用；但硬考核 14+ fps 只有 D=64 过线。

**来源**：`memory.md` §25；`MOSAIC_RK3588_20261026.md` §22、§19.2；`falsified_archive.md` §五十八。
**讲述**：1.5 分钟。**这是全篇最容易被追问的一页**，差账行一定要讲。

### P07 · 战线 B：NPU 之战 —— 击碎静默失效与 FLOPs 幻觉

**主张**：NPU 不是算得慢，是**算的东西和算的方式都不对**。

**版面**：左右双栏（本页同时承担「战线 B 章节页」与「B1+B2 详情页」两个角色，参考稿已如此设计，不要再加章节页）。

**左 · 战果 B1：算子回退清零**（配八段数码管「1 → 0」意象）
- **抓捕暗礁**：发现模型有 **1 个布局计算算子**悄悄落到 CPU
- **特征**：不抛异常、不改指标！让「全在 NPU 上」变成谎言
- **击破**：用**步长卷积**代替需 transpose 的算子，CPU 算子清零。加速至 **103.7 ms** 且精度 Exact
- **铁律**：把「静默失效」作为交付硬闸门。**永远 PASS 的断言等于没有检查**

**右 · 战果 B2：禁用 FLOPs 外推**（配折线图：MAC 算力 −6.8% 几乎平，真实时延 −46.5% 陡降）
- **魔幻实测**：删掉 P0 支路后，Conv MAC 算力仅下降 **6.8%**，但时延却暴降 **46.5%**（103.7 ms → **55.5 ms**）
- ✗ **曾被误判**：用 MAC 算力推导耗时
  ✓ **真相**：NPU 的天花板卡在**张量空间乘积**（H×W ≤ 16384），最劣形状拖垮了整个硬件调度
- **铁律**：严禁用 ONNX FLOPs 估算，必须以 **RKNN 算子表实测**定生死

**来源**：`heatmap_npu_trial0474.md` §零、§六之二、§六之二·4；`rules.md` §四·9e。
**讲述**：2 分钟。

### P08 · 战果 B3｜RGA 硬件画布：3 次前向压成 1 次

**主张**：突破 Multi-Scale 的 NPU 瓶颈 —— PC 端三尺度独立推理需 3 次前向，板卡仅能跑 ~3 fps，不可交付。

**版面**：左侧两段文字卡；中央 640×640×3 画布示意图；右侧成果卡。

**画布图标注**（本页视觉主锚点）：
- 画布 640×640×3
- native 640×512（1:1）
- thumb160（160×128）／ thumb80（80×64）
- 背景 114 · 行 512 起

**左**：
- **支点洞察**：RKNN 耗时由**张量静态形状**决定，与实际像素内容无关！
- **画布大挪移**：将 native 与两个缩略图压入**同一张 640×640×3 静态画布**

**中下**：

### P12 · 收口：主动暴露的现存高危遗留问题

**主张**：未决项不粉饰 —— 以下问题构成了系统精度的「阿喀琉斯之踵」。

**版面**：三张高危卡（红色描边，参考稿原样）。

**L1 · 零丢帧是死前提**
当前锚定等价当且仅当 `dropped == 0`。深缓冲虽兜底，但一旦发生偶发丢帧，系统将产生**静默错位**（无崩溃，特征照常产出）。**深缓冲不能替代该物理约束。**

**L2 · 吞吐刚性红线**
要守住零丢帧，GMC 吞吐必须 ≥ 相机率（≤ 40 ms/帧）。但目前 step10 实测 **60.8~61.2 ms 仍超红线**；40 ms 保底仅在部分选定基准序列上成立。

**L7 · 历史错位缺陷（最高危）**
物理帧号与消费计数器在丢帧时发散。几何配准会错失**一整个物理帧间距**，导致 21 帧中值窗口跨度被压缩。属于典型的**静默数据损坏**。

> 🔧 **状态行（本次新增，参考稿缺）**：截至 10-29，物理帧号锚定改造已落地（`--gmc-phys-anchor 1`，认证路径数值完全惰性）；曾悬而未决的 **22 帧 md5 差异已定位为启动瞬态**（物理帧号 36…78 的偶数帧，lag-42 历史窗口丢 #36 波及 22 个同奇偶组），稳态（≥84）**7045/7045 逐位相同、ΔF1 = 0.000000** ⇒ 不是管线缺陷、精度零损伤。**根治仍需一次离线 `e2fsck -fp /dev/mmcblk0p6`**（ext4 写坏二进制，10-29 第十一轮翻盘）。

**来源**：`00_汇报正文_工程化阶段.md` §4.1；`memory.md` §15.5 / §17.3 / §17.8 / §18.1–§18.5；`falsified_archive.md` §五十七.6。

### P15 · 工程化阶段总结：三大不可逾越的底层认知

**主张**：这三条不是阶段性成果，是这类端侧工程的地基。

**版面**：参考稿原样（深灰石板 + 巨型金属数字 1/2/3 + 闪电裂纹）。

**1 · 静默失效优先于崩溃治理**
在边缘端，不报错但悄悄掉指标的缺陷（如 CPU 算子回退、历史静默堆叠）比 SIGSEGV 更致命。断言必须能被反向证伪。

**2 · 位精确（Bit-Exact）是一切对账的入场券**
没有同图、同帧、**纯空转**的逐字节对照机制，所有关于「量化损失」和「架构收益」的争论都只是伪命题。

**3 · 板卡实测纪律是唯一地基**
用 FLOPs 外推 NPU 延时彻底破产；在 PC 上的毫秒外推到板端毫无意义；多线程加速必须剥离「抢占慢」与「算法慢」。

参考稿是 **Gemini Notebook 生成的整页位图**（每页一张 1376×768 PNG），本仓库另有一套 **SVG 源页 → PPTX** 的可编辑流水线。两条路都行，本设计稿与引擎无关。

**路线 A｜沿用参考稿（Gemini Notebook，位图）**
1. 按本稿逐页改写提示词/文案 → 14 页原样 + 新增 P13 + P14 补方向 B
2. 逐页重出图 → 人工比对数字与脚注
3. ⚠️ 位图不可编辑、不可搜索、md5 一改全页要重出 —— 后续每次改数字都要整页重做

**路线 B｜回到本仓库 SVG 流水线（可编辑，推荐）**
1. 在 `manu/report/assets/svg_source/` 下新建 15 个 SVG 源页（沿用现有命名：`01_cover.svg` … `15_thanks.svg`）
2. 每页**只挂一个视觉主锚点**，文字按本稿「内容块」写，不超 8 条/栏
3. 跑 `svg_quality_checker.py`（布局质量门，要求 0 warning / 0 error / 0 blocking）
4. 跑 `svg_to_pptx.py` 出 PPTX（目标：原生 DrawingML 形状、无位图）
5. 跑 `export_outline_md.py` **重新导出** `01_幻灯片大纲.md`（它是生成物，不要手改）
6. 三侧 md5 校验（本地 = SSHFS = 服务器），并把 `02_数据溯源.md` 补上 P13 与本稿 6 处口径修正

## 一、项目背景与业务问题定义

### 1.1 业务场景

低空安全 / 无人机防控。吊舱或固定哨塔上的红外相机，需要在**复杂背景 + 平台运动 + 低信噪比**条件下稳定发现并跟踪远距离无人机。

### 1.2 物理难点（决定了技术路线）

远距离红外无人机在焦平面上**不是「有轮廓的小目标」，而是一个局部的 PSF 冲激**：

- 目标只有 **1~3 像素**，没有稳定纹理、部件、边缘；
- 目标响应可能**低于同帧全图噪声极值**；
- 相机运动会把静态地物变成结构性差分边缘（伪目标的主要来源）；
- 目标会瞬态暗化、闪烁、翻滚、悬停；
- 传感器坏点、地表热斑、云层纹理、飞鸟与无人机响应同构。

⇒ 因此**传统 Anchor 回归在 1~3 px 目标上会亚像素梯度塌缩**，必须换表征（Heatmap 点回归）；而**单帧信息不足**，必须引入运动对齐（GMC）与时域建模；而**信息冗余又会放大虚警**，必须配套后处理门控。三者缺一不可，这是项目为什么长成现在这样的形态。

### 1.3 三重硬约束（同时成立才算交付）

| 约束 | 具体判据 |
|:--|:--|
| 业务域精度 | 龙泉山 24 序 F1 ≥ 0.88、R ≥ 0.85、FAR ≤ 0.030，且**逐序列**能解释（pass 序列数是硬指标） |
| 端侧实时性 | RK3588 NPU int8 单帧 ≤ 21 ms（后收紧为 ≤ 20 ms）、吞吐 ≥ 14 fps、延时 p95 可接受 |
| 口径纪律 | 同帧、同 GT、同工作点、同解码器；结论必须**可复现、可对账、可移交** |

### 1.4 立项第一周的判断（未走弯路的原因）

入职首周就完成了三件决定后续十周不走弯路的事（`manu/docs/weekly_reports/2026-09-10_*.txt`）：

1. **公司自有数据诊断**：场景多样性严重不足（几乎都是开阔空域、固定机位、单一天空背景）、目标尺度严重失衡（中大型为主，**1~5 px 远距样本几乎为零**）⇒ 定论：**直接用自有数据研发底层特征会「虚假收敛 + 场景过拟合」**，先引入 Anti-UAV 公开标杆数据集做通用基座，自有数据留作领域迁移验收。
2. **模态选型**：可见光在逆光/树林/雨雾/夜间的 1~3 px 目标分离度极差；红外依赖热辐射、具备全天候透雾穿云能力，目标呈各向同性高斯冲激 ⇒ **全面以红外为主攻方向**。
3. **防泄漏 5-Fold 划分**：照搬顶会 *A Simple Detector with Frame Dynamics is a Strong Tracker* 的**相似度连通图 + DFS 聚类 + 贪心均衡切分**，从图论层面切断同源序列跨折泄漏。**这一步是后面所有官方域数字可被信任的前提。**

### 3.1 算法范式与业务域突破（亮点 1 ~ 4）

#### 亮点 1｜表征范式重构：从 Anchor 框回归转向 Heatmap 点回归
- **核心突破**：针对 `1~3 px` 红外微目标在传统 Anchor/Bbox 下发生亚像素梯度塌缩的问题，放弃框回归范式，重构为 P2 支路 + stride-2 P1 高分辨率点回归输出头（`320×320` 输出，`21.48 G MAC`）。
- **硬核数据**：官方域单帧 F1 从 **`0.6565` 跃升至 `0.906361`（`+25.0 pp`，TP `21,643` / FP `1,004`）**，叠加系统级时空后处理后达 **`In-BBox F1 0.9209`**。
- **支撑细节**：
  - 立项首周就完成了防泄漏 **5-Fold 划分**（相似度连通图 + DFS 聚类 + 贪心均衡），这是后面所有官方域数字可被信任的前提；规范验证大盘 **31,613 帧 / 25,111 GT**。
  - 输入通道从 4 个候选里选出 **3 通道短时序差分** `[I_t, |I_t-I_{t-1}|, |I_t-I_{t-2}|]`（短帧差压掉 80 %+ 静态地物杂波；`t-8` 大跨度因机动目标漏检被否；signed diff 会偶极子相消被否）。

### 3.2 RK3588 端侧加速与实时流水线架构（亮点 5 ~ 7）

#### 亮点 5｜RK3588 白盒时延成本公式与输入零拷贝加速
- **核心突破**：清理全部计算算子回退（`fallback / unsupport / exceed` 全为 0）；基于 RKNN 逐层周期与带宽表拟合出端侧物理公式 **`rknn_run (ms) ≈ 13.94 + 0.902 × NPU周期(百万) + 0.143 × RW(MB)`**（7 组实测残差 `≤ 1.37 ms`），定量定标该芯片存在约 `13.9 ms` 硬件固定底噪（同板标准 YOLO26n 需 `23.66 ms`〔§77 实测 23.658 / §91 同板复测 23.805〕、官方 YOLOv5s 需 `26.2~26.3 ms`〔§91 实测 26.311〕），将优化火力精准锁定在可动算力与带宽税；同时揭示混合精度/QDQ 会导致输入回退 FP16（`45.41 ms`），锁定全图 INT8 + `pass_through=1` 零拷贝路径。
- **硬核数据**：`pass_through=1` 使 `inputs_set` 从 `15.054 ms` 降至 **`0.213 ms`（`71×` 提速，输出 Hash 逐字节不变）**。
- **支撑细节**：
  - **零算子 fallback 是交付硬闸门**：用 RKNN 算子表 Target 列逐项判定，CPU 侧只允许 Input/Output 算子；**验收输出不得靠 `grep`/`sed` 过滤判成败**（过滤会把失败伪装成成功）。
  - **同板同口径参照系**：标准 YOLO26n `rknn_run` **23.658 ms**、NPU 合计 24.445 ms ⇒ **40.91 fps**；Rockchip 官方 YOLOv5s demo 约 **26.2~26.3 ms** ⇒ 本板 NPU 有效吞吐只有 **~256–282 GOPS**（标称 6 TOPS 的 ~4 %）—— 这是**板卡规格事实，不是模型问题**。
  - **禁止用 MAC/FLOPs 外推 NPU 时延**：算术量与墙钟可背离近 7 倍；成本模型必须实测拟合。
  - **QDQ/混合精度陷阱**：`InputOperator` 被变成 FLOAT16 ⇒ `inputs_set` 45.41 ms vs int8 0.34 ms ⇒ 「延时意义上根本不是 int8 模型」。
  - **fp16 零拷贝反亏**：驱动把「暂存输入」挪进 `rknn_run`（+13.6 ms fp16 / +6.2 ms int8，≈180 MB/s 慢拷贝）⇒ 整帧净亏 3.2 ms ⇒ 零拷贝不推广；**真正可用的杠杆是 CPU 绑核**（45.41 → 11.15 ms，4.1×，零精度影响）。
- 📍 出处：§77.4·§77.5·§77.9b·§77.9c / §11.2·§11.3

#### 亮点 6｜多尺度单次前向拼图（Canvas Mosaic）与稀疏抽峰后处理
- **核心突破**：利用 RK3588 的 RGA 硬件完成 `640 / 160 / 80` 三尺度特征拼图，实现**一次 NPU 前向完成三尺度检测**（直接省去 `2/3` NPU 前向计算量）；针对后处理瓶颈，利用红外热图极度稀疏的特性重写抽峰逻辑，跳过 `99.8%` 无效背景像素。
- **硬核数据**：RGA 拼图仅耗 **`1.095 ms/帧`** 且黄金池 **`ΔF1 = +0.000000`**；后处理耗时从 `45.72 ms` 压至 **`0.6753 ms/帧`（`71.3×` 加速，输出逐字节不变）**。
- **支撑细节**：
  - **NPU 时间不变**：`rknn_run` **100.259 ms** == 单尺度 101~102 ms ⇒ 省下的 `2/3` 计算量**没有变成延迟收益**（真正的瓶颈是拼图装配与后处理）。
  - 端到端 e2e 全量：F1 **0.891676**，总账 **−0.006018（相对 0.67 %）**；三尺度 7030/7030 帧特征 md5 逐位相同。
  - **稀疏化原理**：红外热图前景仅 **1,822 px / 983,040（99.8 % 是白扫）**；GPU 后处理实测比 CPU NEON 慢 1.6× 且有 **54.324 ms 首帧尖刺**（OpenCL 懒初始化）⇒ 默认切 sparse，GPU 保留为可选 env。
  - 其它提速档：GMC 拟合分辨率 320×256 → 160×128 **3.05×**（召回不变，feature md5 7161/7161 逐位相同）；`anchor_step=10` **2.09×**（但最坏帧 246.869 → 491.590 ms 翻倍 ⇒ 需重新认证）。
  - 后续被更优路线超越：No-GMC 单次直出 **7.64×**（100.259 ms → 13.131 / 19.306 ms）⇒ 拼图路线定位为「技术验证 + 备选交付形态」。
- 📍 出处：§11.6–11.7 / §二十七·§二十八·§二十九

#### 亮点 7｜「GMC 零丢帧」异步流控架构与物理帧号锚定
- **核心突破**：重构三级解耦异步流水线（双 NPU 上下文 `1.84×` 加速），定位出早期相机入口丢帧会摧毁 GMC 21 帧时序配准链的致命缺陷，将背压丢帧点下移至无状态特征缓冲，确保上游配准链零丢帧（`dropped = 0`）；设计物理帧号锚定（`phys_anchor_`）解耦外部跳号与内部环形缓存，消除窗口限流死锁与静默配准错位。
- **硬核数据**：累计加速 **`2.69×`**，端到端吞吐从 `5.74 fps` 提升至 **`14.037~14.838 fps`（`2.45×`）**，且板端与服务器精度**逐位一致（`ΔF1 = +0.000000`）**。
- **支撑细节**：
  - **丢帧真根因（两次误诊后定位）**：不是 CPU 不够（实测总占用仅 2.57 核/8 核），而是 ingest 被「历史窗口护栏」限流的**自我维持死锁** ⇒ 护栏放行速率 = 引擎完成速率 ⇒ 挡 ingest ⇒ 队列抽干 ⇒ 空等 ⇒ 周期 63.4 → 85.9 ms ⇒ 放行更慢。
  - **GMC 历史锚定缺陷**：消费计数 `abs_counter` 与物理帧号 `next_id` 在丢帧时发散 ⇒ GMC 取的 `ring_[abs−2]` 不是物理 lag−2 帧 ⇒ **静默错位**（无崩溃无报错）⇒ 锚定等价性**成立当且仅当 `dropped == 0`**。
  - **前 300 帧是陷阱**：前 300 帧角点均值 195.6 vs 全序列 389.4（一半），`gmc_fit` 29.318 vs 62.976 ms/帧 ⇒ **全序列 `dropped == 0` 才是唯一可交付判据**。
  - **深队列定量证伪**：q=8 → q=48（6×）丢帧 5131 → 5055（**仅改善 1.5 %**）⇒ 深队列能吸收尖峰、不能吸收持续速率差。
  - **吞吐模型**：预测 377 vs 实测 370（**误差 1.9 %**）；吞吐硬天花板 ≈ **15.3~15.6 fps**（理论 17.51 fps 已作废）。
  - **三级解耦 + 轮转游标**：两 NPU service 产能失衡 1.63:1 → 1.52:1 → 1.44:1 → **1.00:1**；per-service 3042:3048 = **1.002:1**。
- 📍 出处：§11.8–11.11 / §14–§18 / §15.5·§16.4

### 3.4 评测基建与工业级 SDK 交付（亮点 10 ~ 11）

#### 亮点 10｜可证伪评测基建：NanoBench + 三轨门禁 + 反向注入审计
- **核心突破**：先造高精度尺子再做模型搜索——构建微小目标专用评测台 `NanoBench`（分层覆盖 `nano 4,232 / micro 3,283 / small 11,796 / regular 5,800`），建立三级漏斗判别机制，并通过反向故障注入审计评测脚本本身。

## 九、口径风险自查（答辩时主动声明，比被问出来强十倍）

1. 🔴 **「`gate_report.json` 的 `verdict = FAIL`」≠ 交付失败** —— **这一条必须答辩时第一个讲清楚**。`gate/NANO_1105000_ep5_official/gate_report.json` 的 FAIL 来自它的 T1 门设的是**早期冻结红线 0.905736**（红线 0.900736），而**本项目所有臂（含现行基线 v2.2 的 T1 = 0.890494）都过不了这一条** ⇒ **判交付必须用任务书口径（§136.6），不能用 `gate_report` 的 `verdict`**（§198.1 / §199.1）。**这是判据参照系的选择，不是隐瞒**：参照系不同结论就不同，这本身是本项目的一条结论。
2. **94.747 %（业务域）与 0.890494（官方域）不可横向比**：前者是龙泉山 24 序系统级在线指标（GT 分母 133,257），后者是 Anti-UAV 31,613 帧单帧离线指标（GT 25,111），特征语义（GMC / no-GMC）与匹配口径均不同。
3. **业务域交付档必须写清 m=0 还是 m=6**：权威报告两处「24 序 Δ=3 replay F1」是**不同配置**（m=0 裸配置 94.7861 / FAR 0.025523；m=6 交付档 **94.8094 / FAR 0.024337**）。
4. **9863 的 19.306 ms 是构造保证，从未在交付板实测**（只改 loss 不改图 ⇒ 同图结构等价推得）；现行基线 v2.2 的 **19.611 ms 是真板实测**。
5. **新板整体慢 11~22 %**，连在位交付件 `trial_0031` 自己都是 23.528 ms ⇒ 现行临时判据改为「**同会话不慢于 0031 × 1.02**」（红线 19.989 ms）。**绝对「≤20 ms」是否按新板重定标，尚待裁决。**
6. **现行基线的 nano 0.7157 仍含种子成分**：9863 同配方换种子 9912 = 0.6933、同臂其它 epoch 0.6897~0.6942 ⇒ 因此**打平线双报（严格 0.708648 / 稳健 0.70098）**，且升轨纪律要求**同家族六项全过臂 n ≥ 4**。
7. **NanoBench 4 px 严格档并未随 8 px 主档同步改善**（9863 的 0.647212 低于 0080 的 0.6668）；另有基准口径缺陷待修（`gt_bboxes` 实为原图像素却再乘 0.8 ⇒ 物理 nano 实占 14.64 %，参照卡写 16.85 % 偏高 2.2 pp）。
8. **PTQ 校准集轴被证伪**（除干净集子集口径外全量口径不兑现）；**QAT 当前形态不可用**（四刀定位到 heatmap 头被搬坏）。部署建议维持 toolkit 原生 int8 + 逐轨阈值重标定。

## 十、预设问答（评委必问）

**Q1：官方门禁 verdict 都是 FAIL，你凭什么说达标？**
答：本工程采用的是**六项相对判据**（nano / nano4 / F1 / T1 / T2 虚警 / T3 + 板卡时延），参照系是「当前在位交付件」而非早期冻结红线。这不是挑宽松标准——恰恰相反，我在 11-13 识破了一个 n=8 复现只有 1/8 过六项的「运气臂」，并**主动放弃**了一条看起来领先 3 项的候选。同时我也把这件事写进了文档而不是藏起来。

**Q2：业务域 94.8 % 和官方域 0.89 到底哪个好？**
答：**不可比**，这是两个不同的问题。94.8 % 回答「在实战域、在线系统上能不能用」；0.89 回答「在通用域、单帧离线上精度如何」。两个数唯一能比的维度是**同一份 GT 上的同口径变化**（例如 RC2 相对冻结基线 F1 +4.14 pp 且 FP 少 1,479）。我所有的结论都建立在这种同源对照上。

**Q3：nano 提升里有多少是种子运气？**
答：我**主动量过并双报**。同配方换种子：sw1.0 差 0.07 pp、sw4.0 差 1.04 pp、sw5.0 差 **1.53 pp** ⇒ 高 sw 区单臂读数不可单独作轴效应证据。这也是我把 `trial_12869` 判成运气臂（n=8 只有 1/8 过）、并要求升轨必须 n ≥ 4 的原因。

**Q4：为了速度，精度是不是被牺牲了？换 T1 的 −1.59 pp 值不值？**
答：那 1.59 pp 是**「切掉 P0」的定价，不是配方能买回来的**——P0 highway 实测成本 **+17.13 ms**，加回去就是 ~30 ms，远超 20 ms 预算；而同语义对照下，13.131 ms 结构与 55.484 ms 结构的 T1 只差 **0.19 pp**（此前「欠 1.4~2.0 pp」是跨语义比较造成的假象）。换来的 T3 **+5.06 pp / 虚警 −77 % / NPU 7.64×**。而**现行基线 v2.2 的 T1 = 0.890494 已经高于 0031 的 0.885997**——速度与精度在最新一代上同时改善了。

**Q5：19.6 ms 的结论在现在的板子上还成立吗？**
答：**现行基线 v2.2 的 19.611 ms 是真板实测**。但新板（Orange Pi CM5）整体比旧板慢 11~22 %，连 0031 自己都是 23.528 ms，所以「绝对 ≤20 ms」在换板后已不适用于旧基线，判据我改成了「同会话不慢于在位交付件 × 1.02」并明确标注为**临时判据、待裁决**。我同时做了热学终验：54 分钟真实交付负载下 cooling 0 次 / 降频 0 次 / PVTM 未触发 / 内核事件 0，NPU 占空比 97.7 %。

**Q6：这些数字别人能复现吗？**
答：有四层证据：① **独立复算**——审计脚本不 import 被审报告的任何函数，从产物 JSON 重算（34/34 PASS）；② **逐位级一致**——端到端 7,030/7,030 帧特征 md5 相同、检测逐字节相同，ΔF1 = +0.000000；③ **门禁可证伪**——审计脚本做 6 次反向注入全部被捕获，交付入口做正反两路自证（篡改即 `[GATE][FAIL]` exit 3）；④ **一键复跑**——交付包内含独立复跑入口与全部报告生成器源码，冷启动 35/35 IDENTICAL。

**Q7：为什么敢动底模结构（换 P3 层级、加 late_upsample、换 all-relu）？**
答：三个前提：① 先量后动——P0 成本、层级成本、激活函数成本全部先在板卡上实测定价（P0 +17.13 ms；SiLU 比 relu 贵 **+6.7~+8.8 ms**，高于周期表显示）；② 受控渐进残差，**禁解冻底模**（铁律六）；③ 同源受控 A/B + 代码级等价证明（`epochs=5` 逐位等价 ⇒ 算力 ÷4）。而且其中有一半的「结论」最后被证明是**评测口径缺陷**而非模型问题——这正是我坚持可证伪评测体系的原因。

**Q8：十个星期你最大的收获是什么？**
答：**学会区分「我以为对的」和「数据支持的」。**这个项目里我主动证伪了 75 条以上自己写进结论的认知，包括「混训比例是命门」「丢帧会让精度灾难性下降」「校准集影响很小」「前 300 帧可以代表吞吐」「深队列能顶住持续亏空」等等。每次证伪都留证在 312 KB 的证伪档案里。**一个能自我推翻的结论体系，比一个漂亮的数字更值钱**——尤其在要交付给硬件、要在实战域上用的场景里。

**Q9：现在最大的风险 / 下一步？**
答：三个已知风险 + 三条下一步（详见 §十一）。

## 一、算法范式与业务域突破（亮点 1 ~ 4）

### 亮点 1｜表征范式重构：从 Anchor 框回归转向 Heatmap 点回归
- **核心突破**：针对 `1~3 px` 红外微目标在传统 Anchor/Bbox 下发生亚像素梯度塌缩的问题，放弃框回归范式，重构为 P2 支路 + stride-2 P1 高分辨率点回归输出头（`320×320` 输出，`21.48 G MAC`）。
- **硬核数据**：官方域单帧 F1 从 **`0.6565` 跃升至 `0.906361`（`+25.0 pp`，TP `21,643` / FP `1,004`）**，叠加系统级时空后处理后达 **`In-BBox F1 0.9209`**。
- 📍 出处：§三.1 / 周报 09-17·09-24 / memory §1、§77.1

### 亮点 2｜业务域实战交付：龙泉山 24 序列三条核心判据全过
- **核心突破**：完成复杂山体与云层干扰场景下的领域迁移与端到端时空后处理调优，锁定正式交付模型（`ir_uav_det_rk3588_v1.0.rknn`），全面达成业务准入标准。
- **硬核数据**：龙泉山 24 序 F1 从 **`90.605%` 提升至 `94.747%`（`+4.14 pp`）**；虚警率 FAR 从 `0.0298` 降至 **`0.0208`（下降 `30.2%`，留出 `30.6%` 安全裕度）**，误检 FP 从 `4,919` 降至 `3,440`（**直降 `1,479` 个**），**`21/24`** 序列达标。
- 📍 出处：§2.5.4 / §三.2

### 亮点 3｜能量门控后处理：不改冻结阈值的虚警过滤器
- **核心突破**：针对高难杂波序列误检痛点，在严格保持冻结基础阈值（`th_base = 0.30`）不变的前提下，引入**多尺度热图总能量过滤（`area ≥ 1, abs, sums ≥ 14.5`）**，通过累加局部放大尺度下的响应能量总和，精准区分"有实体的暗弱真目标"与"只有尖峰、没有底座的孤立杂波毛刺"。
- **硬核数据**：在 **16 条未参与调参的样本外序列**上重放验证实现 **`16/16` 全正向增益**（F1 中位数再涨 **`+0.78 pp`**，高难序列虚警再砍 **`48%~63%`**）。
- 📍 出处：§76.5（16/16 泛化验证表：ΔT3 +0.6765 ~ +1.0846 pp，中位数 +0.78 pp，T3 FP 削减 −23.6%~−45.7%）／§76.3·§75（T3 FP 171 / 175 / 176 ⇒ −48.2%~−48.7%~−63.49%）

### 亮点 4｜面向极小目标的轻量结构演进与最新微调突破
- **核心突破**：先在板卡逐项实测结构延迟（P0 highway 耗时 `+17.13 ms`、SiLU 比 ReLU 贵 `+6.7~+8.8 ms`），设计 `late_upsample` 将计算分辨率与输出分辨率解耦（仅增 `2.9 ms`）；进一步针对小目标"召回 vs 虚警"帕累托硬权衡，引入**靶向小目标 Copy-Paste（`cp`）增强**（仅粘贴 `≤ 12 px` 微目标补齐仿射缩放丢失监督，不抬高背景响应），并证伪跨盆地 Model Soup 崩盘（F1 跌至 `0.24~0.65`）后验证**同训练轨迹父子汤**零推理成本融合。
- **硬核数据**：单帧模型延迟从 `55.48 ms` 压缩至 `13.131 ms`（`4.2×` 加速）及 **`19.611 ms` 交付级基线（`Baseline_v2.2`）**；靶向 Copy-Paste 使 `nano@4px` 跃升 **`+2σ` 至 `0.6675`** 且守住黄金池虚警 **`≤ 1`**；同盆地父子汤在三项核心指标上同时超越单体成员（`nano 0.7214 / nano@4px 0.6558 / F1 0.8906`）。
- 📍 出处：§84 / §77.9b / §95 / §170（cp 轴）/ §195（策展汤证伪）/ §198（父子汤 `1105000`：nano .721408 / nano4 .655718 / F1 .890615 / t1 .890596 / t3 .948792 / 19.731 ms）
- ✅ 已核：`nano@4px 0.6675` **有出处** —— 即 `1102001@2`（从 `1100275@1` 抛光，sw4.0 / lr0.05 / lrf0.2 / l2.001 / **cp0.05**），读数 **nano@4px = 0.667533（+0.012，富余 +2σ）**，日志确认 cp 生效（`[CP] … prob=0.05 max_src_px=12.0 feather=2.0 per_img=2`）。⚠️ **但边界要一起讲**：该臂 **nano 掉 0.8e-2（0.712902）** ⇒ **cp0.05 强度不足**，"守住黄金池虚警 ≤ 1" 未在该臂单独记录 ⇒ 建议讲法改为「**CP 是与 sw 正交的杠杆，已在 `nano@4px` 上打出 +2σ 富余（0.6675）；但 cp0.05 太弱会把 nano 拉低 0.8e-2 ⇒ 本轮 cp 轴加码到 ≥ 0.15**」，比硬报"且守住 ≤ 1"更抗追问。

## 二、RK3588 端侧加速与实时流水线架构（亮点 5 ~ 7）

### 亮点 5｜RK3588 白盒时延成本公式与输入零拷贝加速
- **核心突破**：清理全部计算算子回退（`fallback / unsupport / exceed` 全为 0）；基于 RKNN 逐层周期与带宽表拟合出端侧物理公式 **`rknn_run (ms) ≈ 13.94 + 0.902 × NPU周期(百万) + 0.143 × RW(MB)`**（7 组实测残差 `≤ 1.37 ms`），定量定标该芯片存在约 `13.9 ms` 硬件固定底噪（同板标准 YOLO26n 需 `23.66 ms`、官方 YOLOv5s 需 `26.21 ms`），将优化火力精准锁定在可动算力与带宽税；同时揭示混合精度/QDQ 会导致输入回退 FP16（`45.41 ms`），锁定全图 INT8 + `pass_through=1` 零拷贝路径。
- **硬核数据**：`pass_through=1` 使 `inputs_set` 从 `15.054 ms` 降至 **`0.213 ms`（`71×` 提速，输出 Hash 逐字节不变）**。
- 📍 出处：§77.4·§77.5·§77.9b·§77.9c / §11.2（QDQ ⇒ FP16 45.41 ms）

### 亮点 6｜多尺度单次前向拼图（Canvas Mosaic）与稀疏抽峰后处理
- **核心突破**：利用 RK3588 的 RGA 硬件完成 `640 / 160 / 80` 三尺度特征拼图，实现**一次 NPU 前向完成三尺度检测**（直接省去 `2/3` NPU 前向计算量）；针对后处理瓶颈，利用红外热图极度稀疏的特性重写抽峰逻辑，跳过 `99.8%` 无效背景像素。
- **硬核数据**：RGA 拼图仅耗 **`1.095 ms/帧`** 且黄金池 **`ΔF1 = +0.000000`**；后处理耗时从 `45.72 ms` 压至 **`0.6753 ms/帧`（`71.3×` 加速，输出逐字节不变）**。
- 📍 出处：§11.6–11.7 / §二十七

### 亮点 7｜"GMC 零丢帧"异步流控架构与物理帧号锚定
- **核心突破**：重构三级解耦异步流水线（双 NPU 上下文 `1.84×` 加速），定位出早期相机入口丢帧会摧毁 GMC 21 帧时序配准链的致命缺陷，将背压丢帧点下移至无状态特征缓冲，确保上游配准链零丢帧（`dropped = 0`）；设计物理帧号锚定（`phys_anchor_`）解耦外部跳号与内部环形缓存，消除窗口限流死锁与静默配准错位。
- **硬核数据**：累计加速 **`2.69×`**，端到端吞吐从 `5.74 fps` 提升至 **`14.037~14.838 fps`（`2.45×`）**，且板端与服务器精度**逐位一致（`ΔF1 = +0.000000`）**。
- 📍 出处：§11.8–11.11 / §15.5·§16.4（物理帧号锚定）/ §17.4（双 ctx 1.84×）/ §18（吞吐天花板）

## 三、实时链路攻坚与数据标注工具链（亮点 8 ~ 9）

### 亮点 8｜Fast Infer + 出框门：攻克 `320 ms` 实时链路滞后
- **核心突破**：定位出实时推理链路的滞后属于结构性问题，经实测证伪单纯调检测阈值或加运动学外推均无效后，设计并验证"出框门（Out-of-Box Gate）"机制作为唯一有效控制旋钮，并建立 15 字段逐位交付门禁与正反两路自证机制（任何配置篡改立即触发 `[GATE][FAIL]` 拦截）。
- **硬核数据**：老逻辑滞后 `FAR 0.059277`（四档全 FAIL）逆转为 **`F1 94.8094` / `FAR 0.024337` / `hit@5px 86.97%` / `CLE p95 7.0663 px`（三门全 PASS，`Δ=8` 档 `0.029608` 亦过线）**。
- 📍 出处：§39.1 / §45·§47 / §67

### 亮点 9｜"去框化"极简点标注方案与自研工具链（`PointAnnotator`）
- **核心突破**：
  - **去掉 Bbox 的单点标注规范与预推冷启动**：针对 `1~3 px` 红外微目标传统矩形框（Bbox）边界模糊、拖拽四边极耗时且易引入尺度噪声的痛点，结合点回归模型特性**彻底取消 Bbox 拉框环节，改为"单点中心定位"极简标注规范**，从源头大幅削减人工操作工作量；同步搭建"模型多尺度预推播种 + 时空轨迹辅助筛查 + 防泄漏域切分"冷启动流水线，排查并规避 OSD 视频非等比裁剪偏移陷阱（直接叠点会偏 `200~300 px`），锁定纯净原始视频源（平均偏差仅 `(+3.7, +1.0) px`）。
  - **自研桌面点标注工具（`PointAnnotator`）**：针对微小目标肉眼难辨、逐帧重标效率低的问题，自研跨平台 Windows 桌面端 `PointAnnotator` 及配套操作手册，集成 **`8×` 像素级放大镜、帧间坐标自动继承、模型预推双残影一键快切与原子写盘防损坏机制**，将测试人员单帧操作从"反复拉框调边界"简化为"单点微调确认"。
- **硬核数据**：完成新场景（纵横 `58/58` 序列、`173,781` 帧）全量预推与底稿生成，自动产出 **`86,595` 个高置信预标注点位**（检出覆盖率 `49.8%`，`FAR 0.0176`），完成防泄漏数据集划分（基础档 `val 26 / train 29 / ignore 3`；后续**时空轨迹档**升级为 `val 30 / train 24 / ignore 4`、预标注 **96,174** 个）；自研 `PointAnnotator` 工具通过 **`101/101` 项自动化自检**，预推坐标与全幅画面逐帧核对 **`0` 处偏差**，已直接交付测试团队投入生产标注。
- 📍 出处：§173 / §91.9 / `manu/memory/point_annotator_tool.md`（放大镜 248×248 取 31×31 邻域）

## 六、需要你拍板的 4 件事

1. **时长与形式**：多久？多少页上限？是否现场演示（PointAnnotator / 板卡 / OSD 视频）？
2. **听众构成**：有无非技术评委？有则把「业务域交付（亮点 2）+ SDK 交付（亮点 11）」提到最前，评测基建（亮点 10）压到 1 页。
3. **口径策略（新增，最要紧）**：`gate_report.json` 的 `verdict=FAIL` **不等于交付失败**——它的 T1 门用的是早期冻结红线 `0.905736`，**当前基线 `trial_610000`（T1 0.890494）也过不了这一条**。我建议按**任务书交付红线**（§136.6：F1 > 0.887122、nano ≥ 0.6666、T1 ≥ 0.885997、T2 FP ≤ 20、T3 ≥ 0.948330、int8 ≤ 20 ms）主动讲，并顺带说明「内部严格六项」是**更严的研发判据**，两者分开记账。
4. **还缺哪块**：有没有**没进 memory 系统**的工作（对外沟通、跨部门协作、硬件协调、帮同事的事）？这类在答辩里往往比技术细节更能体现「转正候选人」的价值——补给我我加一节。
